# Agent Chat UX 原型：先处理项目，还是先开始会话？

这组原型不再共享同一种页面状态。它们分别验证五种不同的「项目—会话」关系，同时覆盖 Agent、模型、权限、图片、语音和移动端。

## 当前实现的问题

- Composer 的 `active` 同时由输入焦点、设置弹框和语音状态驱动，输入区域因此在内容没有变化时也会改变高度。
- Agent、模型、权限和思考强度被压缩为一条摘要，再放进同一个长弹框；不同作用域没有被表达。
- 模型使用纵向 Radio 列表，数量增长后只能线性滚动。
- 图片能粘贴、删除，但 Composer 缩略图没有大图检查路径。
- 语音功能完整，但状态条、候选和详情持续挤压 Composer，布局不稳定。
- 移动端基本沿用桌面信息架构，仅把 Dialog 改成 Bottom Sheet。

## 五套交互模型

### 01 自动继承：`chat-fluid-dock`

点击“新会话”立即创建，并继承当前项目。项目胶囊始终在 Composer 中可见，可以随时切换或移除。这是推荐的正式基线，决策最少。

### 02 意图推荐：`chat-command-hub`

从无项目会话直接输入。系统理解任务后，在发送前推荐可能相关的项目；用户可以接受或忽略。适合拥有大量项目、普通问答和编码任务混用的场景。

### 03 快捷起点：`chat-context-capsules`

新建时直接展示最近项目、无项目和浏览全部项目。选择即进入会话，没有项目详情页或第二次确认。适合隔离要求较高的团队。

### 04 项目导航：`chat-focus-canvas`

项目是稳定的左侧工作范围，会话在项目内部创建。Agent、模型、权限和上下文移到独立 Inspector，Composer 只负责消息。适合桌面开发工作台。

### 05 按需绑定：`chat-mobile-deck`

普通对话、图片粘贴和语音无需项目；只有读取项目文件、运行命令或调用项目工具时才要求绑定。适合移动端和聊天优先的使用方式。

## 共同设计约束

- 输入高度只由内容决定；焦点仅改变视觉反馈。
- Agent、模型和运行模式拥有独立入口，不再藏在一条模糊摘要里。
- 模型选择支持搜索、最近、收藏和能力筛选。
- 图片支持文件选择、直接粘贴、缩略图和点击大图预览。
- 语音状态稳定占据一行，结束后转写进入普通可编辑草稿。
- 发送按钮表达发送/运行/停止状态；失败草稿保留属于正式实现约束。
- 所有 Dialog 在窄屏下变为底部 Sheet，并处理底部安全区。
