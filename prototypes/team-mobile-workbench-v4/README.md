# 第四版：完整工作台，项目自己的页面

[打开可交互原型](index.html) · [独立项目 HTML](project-page.html) · [第三版对照](../team-mobile-workbench-v3/index.html)

本轮仅新增独立设计资产，不修改正式 Workbench、RPC、daemon、Pack 或部署。所有会话、选择、授权、Fork 与转发均为演示数据，不会启动 Agent、读取私人文件或执行真实请求。

核对基线：Open `c77f474`、Cloud `a6a6e8b`，dev-agent 配对槽位。本文的“已有”指这两个 revision 的源码能力，不代表新布局已实现或所有现场已验证。第三版“必需协议改动为零”的无条件结论不再沿用：本版把可直接复用、前端微调、未来能力明确分开。

## 这一版可以体验什么

- 会话页：需处理红点与筛选；进入普通问题或项目授权；长请求通过现有交互位置展开。处理后只显示决定已接受，不伪造已经执行。
- 普通信息流：选择两条消息后复制或转发；Fork 选择机器、空间和 Agent，区分原生 checkpoint 与历史重建；目标离线时禁止提交。
- 转发：本机送到草稿，已有草稿保留；跨机器明确标注直接投递。可先切换随行电脑，再模拟恢复连接，体验投递到工作室机器。它是演示确认，不会发出 RPC。
- 会话更多菜单：重命名、归档／恢复、来源关系；导入、运行配置、附件等提供现有能力说明与容器，不伪造可用设备数据。未发送的新会话停在草稿，不挤入历史列表。
- 空间：树形两行名称与浅缩进；空间内进入会话、文件、变更、终端。空间详情仍是全局短操作弹框。
- 工具：只有全局／机器级入口，工具内容是页面；没有用 Tab 再弹出总菜单。文件和终端不会放在全局工具中。
- 发现：未来建议体验明确标注未实现；进入来源会话讨论只追加草稿。第一阶段允许真实空态，不创建扫描服务。
- 公共预览：普通阅读空间与 PM 项目均能打开 HTML；来自会话的反馈回来源草稿，从文件打开的预览不擅自指定会话。
- 项目 HTML：独立文件有两种完全由项目控制的排版，可读相对 JSON；本地勾选不影响真实工作流。没有内置 PM 管理看板。

顶部可切手机／桌面、模拟断线、重置。关闭或刷新会保留演示草稿；原型的 localStorage 不是正式 Session 存储。

## 导航与对象归属

底部／主导航统一为 **会话 / 空间 / 发现 / 工具**。

| 对象 | 入口 | 保持的上下文 |
| --- | --- | --- |
| 会话 | 会话列表、空间内会话列表、来源跳转 | 机器 + workspaceId + sessionId；现有订阅与 TimelineView |
| 空间工具 | 当前空间的文件、变更、终端 | 打开时固定机器 + workspaceId；不随另一个会话悄悄变更 |
| 全局工具 | 我的电脑、设备、设置、产品反馈 | 宿主／账号作用域，是否存在由宿主决定 |
| 机器工具 | 后台进程 | 明示目标机器；不伪装成空间进程 |
| 项目页面 | 会话文件链接或空间文件页 | deviceHandle + workspaceHandle + path；有来源时附来源 Session |
| 短操作 | Fork、转发、命名、授权详情、空间详情 | 可用弹框；焦点与返回上下文保留 |

手机一次展示列表或详情；返回保留阅读位置。桌面并列导航、列表、内容。现有多会话标签、草稿与连接 owner 在正式版继续保留；本原型主要验证逐层进入，不声称已经完整模拟桌面所有多标签操作。

空间名称点击在设计中用于浏览空间，显式“新会话”才进入草稿。正式落地新增前端 browse 路径，不能直接改现有 `selectWorkspace` 语义，避免破坏它的新会话首页与深链调用者。

## 逐项工程映射与行为边界

下列路径相对 Open 仓根；均核对过实际实现，而非从原型字段倒推协议。

| 交互 | 既有工程依据 | 修改范围 / 不可改变的语义 |
| --- | --- | --- |
| 会话筛选及红点 | `packages/proto/src/domain.rs::SessionSummary`；`shell/Sidebar.tsx` 的 waiting/failed 状态分组 | 前端投影。红点表示需处理，不等于精确请求数。不能把 running 静默当失败。列表刷新沿用既有 owner，不逐个订阅全机会话 |
| 普通信息流 | `session/TimelineView.tsx`、`timeline.ts`、`store.ts` | 原组件保留，改外壳与手机操作位置；未知工具、历史加载、图片、回合统计不能丢失 |
| 选择 / 复制 | `TimelineView.tsx`、`selection.ts`、`selectionCopy.ts` | 保留可选条目、可见范围、数量上限和剪贴板失败处理。原型仅两条消息，不是替代选择算法 |
| 转发 | `session/ForwardDialog.tsx`、`forwardCapsule.ts`、宿主 ForwardController | 保留预算、详情补全、附件、目标目录与禁用条件。本机 setForwardDraft；跨机 controller.deliver 直接投递，不能统一画成“草稿”。原型不模拟 capsule 裁剪与真实附件 |
| Fork | `session/ForkDialog.tsx`、`MachineCatalogPicker.tsx`；`rpc.rs` 中 session.fork/forkExport/forkImport | 同机器／空间／Agent + 可用 checkpoint + capability 才原生，否则重建。当前进行中的回合也可能走重建，不能统一禁止。不复制存活进程；目标按实际 catalog 校验 |
| 导入 | session.importList / session.import | 候选按空间发现，使用真实候选票据；原型诚实空态 |
| 模型、模式、强度 | Agent catalog、runtime capabilities、现有 Composer 控件 | 按 Agent 支持项展示，不在原型写死公共全集；不新建配置协议 |
| 停止 / 归档 / 命名 | `session/store.ts` 与现有 Session RPC | 按已有状态和权限判断，UI 不另造 Session 状态机 |
| 授权 / 普通问题 | session.get、pendingPermissions、session.respondPermission 与现有交互组件 | 复用持久暂停与恢复。等待时 Composer 互斥；响应成功只表示决定接受。不能承诺跨刷新恢复“已入调度队列”，公开快照不完整 |
| Executor | `session/ExecutorFlow.tsx` 与 session.flow | 保留原生执行信息流，使用现有消息和 Worker Session 链接。不是固定的项目管理 UI；不让前端造失败历史或工作流编辑器 |
| Space 详情、文件、Git、终端 | `shell/Sidebar.tsx`、`ToolsMenu.tsx`、现有面板及 store | 主要是入口和容器调整；保留 CAS、授权、文件与终端会话生命周期。终端页面切走不重建连接 |
| 全局扩展工具 | `shell/tabs.ts::ExtraTab`；Cloud `console/src/CloudApp.tsx` 注入“我的电脑” | 目前 ExtraTab 无 scope。建议增加可选的前端元数据，由 Cloud 显式声明全局；不是 wire 字段。旧扩展未声明时保持旧布局归属，不猜测作用域 |
| 公共文件预览 | `preview/AssetPreviewPage.tsx`、PreviewFloat/PreviewPopoutPage | 复用现有路径解析、资源读取、shared client 所有权；关闭预览不关闭工作台连接 |
| 预览反馈 | 既有 runtime controls、session.artifact 上传和草稿追加 | 先成功保存附件再追加引用；来源无效／只读时降级，不擅自建 PM 会话。已有宿主支持的目标选择不得因原型仅演示来源路径而删除 |

菜单上的按钮不是能力证明。原型对导入、附件、文件管理、运行配置显示说明容器，保留正式组件复用要求；这些没有通过真实后端旅程验收。最终重构必须逐项核对完整现有菜单与可用性，不以静态原型的操作数量宣称全部功能覆盖。

## 项目 UI：模板和文件，不增加业务后台

项目可以在现有工具和执行器支持的范围内，由 PM、WorkflowManager、其他 Agent 与用户共同设计流程。此提案不承诺现有执行引擎能支持任意新流程语义；超出现有 Workflow 合同的需求单独评估，不混入 UI 重构。

GeneHub 提供通用的空间、会话、原生执行记录、文件与预览能力。项目提供管理页面的布局、词汇与数据：研究地图、预算讨论、验收清单、故事板都可以不同。Pack 是可选模板起点，不固定项目管理 UI。更改模板应在项目副本进行，升级不能覆盖用户页面。

首阶段采用如下既有链路：

```text
项目 Agent 使用现有 CLI / 工具读取事实
    → 更新项目 HTML / JSON（项目自己定义格式）
    → 用户从会话链接或文件页打开 Preview
    → 用户通过公共反馈回到会话继续讨论
```

`AssetPreviewPage.tsx` 的 PREVIEW_ASSET_SOURCE 把相对资源请求转给 `client.preview`，可支持 `fetch('./data.json')`。并不只限内嵌摘要。但新数据需要生产者写文件，页面不能根据计时器推断真实进度。更新最好完整写入后替换；原型不实现自动生产者。显示数据读取时间、来源、读取失败并保留旧内容。这里没有新增常驻服务、索引、推送或运行模型。

独立 HTML 双击也能显示内置示例与交互；普通浏览器 file: 限制外部 fetch 时明确提示。GeneHub Preview 可通过既有桥转发相对文件读取。不能为这个静态页面启动 HTTP 服务或塞入专属 loader。

首阶段不要求页面提供“启动 Run”“批准”“激活”“修改工作流”等按钮。页面本地选择和筛选属于页面状态，不是项目事实。真实变更在原会话经现有工具与授权完成。通用原生记录入口保留，以便页面加载失败时查看事实。

当前 Pack 的 WorkflowManager 仍在 Executor 下；原型按实际 Parent 显示。团队关系修正与已有项目迁移单独立项，不通过 UI 伪装为已完成。

## 允许的微调：有预算、可不做

| 项目 | 建议 | 协议影响 |
| --- | --- | --- |
| 工具作用域 | ExtraTab 新增可选 scope 元数据；列出 global / machine / workspace 的前端归属，宿主显式传入 | TypeScript 宿主扩展合同微调；不改 RPC / daemon；旧宿主兼容默认 |
| 空间浏览 | 新增前端 route/view state，保留 selectWorkspace / selectSession 现有语义 | 前端状态，不改服务端对象 |
| 项目页面常用入口 | 首版从文件和会话链接打开；如确需固定入口，另加按机器+空间保存的前端快捷方式 | 可延后；本版不依赖跨端配置、目录扫描或新 Workspace 字段 |
| HTML → 会话交互 | 可选后续能力：只评估 openSession / appendDraft 等窄宿主消息 | **现有桥没有这些动作**。是新增页面-宿主合同，不是“已有 RPC 所以零协议”。需核对 frame source、当前空间、目标资格、文本长度；默认只进入草稿，不直接执行。当前原型不调用它 |

本次落地的必要 wire RPC 新增为零，但这是以上明确收敛的实施范围，不是对未来完整体验的零成本保证。若需要跨端项目页面注册、HTML 实时 Run 订阅、自动建议扫描、页面直接调度，均超出本次微调预算，必须单独立项；不能暗中通过前端全量轮询或通用 RPC 桥实现。

## 发现页的诚实首版

底部为发现留入口；正式首版可以显示说明与空态。原型卡片用于评估来源、依据、忽略、回会话讨论四个交互，并标明示例。

现有 session.list 不能产生“建议”。不为首版增加数据库、调度器或常驻扫描 Agent；也不抓取所有会话快照来生成伪建议。未来独立确定触发方式、读取权限、预算、持久化、去重、过期与忽略语义后再接数据。由人主动在已有会话请求想法仍可现在使用，但不等同后台发现。

## 落地顺序与验收

1. **能力保全清点**：以正式组件为准，逐一登记消息、回合、会话、空间、宿主菜单与移动端入口；标注权限和禁用态。先保留旧组件与 store owner，不复制信息流。
2. **外壳与作用域**：四个入口、空间内工具页、全局工具页；显式工具作用域。保留多标签、草稿、深链、终端连接和返回位置。先完成普通非 PM 空间路径。
3. **现有操作的手机呈现**：选择栏、Fork / ForwardDialog、长授权内容、文件反馈；套用原算法与协议。验证软键盘、safe area、窄屏、不依赖 hover。
4. **公共项目页面**：已有预览路径与文件数据，项目 Agent 输出普通页面；无来源文件不自动指定反馈目标。发现保持空态或有标记示例，不接未经设计的后台。
5. **可选窄扩展单独评审**：只有确有体验必要才做页面宿主桥；接口失败要能回现有会话路径。首版不依赖它。

正式验收需要真实后端验证：同机原生 Fork / 重建 / 跨机、转发草稿与投递、导入候选过期、受管只读、长授权断线恢复、目标机器切换、文件反馈附件失败、无来源预览、终端切页、旧深链和原多标签。执行受影响 Workbench 与现有专项；不为本次静态设计资产跑跨仓全量产品门禁。

回退以外壳开关为单位，旧组件与 owner 留存。首阶段无服务端数据迁移，无新协议版本；不能为了改导航重写 Session、Workflow 或 Preview 运行时。
