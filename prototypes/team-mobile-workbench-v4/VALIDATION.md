# 第四版原型验证

验证日期：2026-09-06。交付范围仅 `prototypes/team-mobile-workbench-v4/` 的设计文件。

## 浏览器检查

使用本机 Chromium / Playwright 打开入口 `file:` HTML，不启动 HTTP 服务，不连接 daemon、不调用 Agent、不提交真实授权。主交互检查 50 项、补充检查 8 项，共 58 项。

- 选择、取消选择、本机转发进入目标草稿、未自动发送、刷新保留草稿。
- 原生 Fork 条件、跨 Agent 重建、离线目标禁用、分支来源。
- waiting/failed 筛选、授权与 Composer 互斥、断线禁用、响应后不伪造执行开始。
- 文件反馈保留来源草稿；无来源预览不指定会话；普通空间与项目都可进入文件路径。
- 空间终端作用域、全局详情、Escape 和焦点留在弹框内。
- 全局工具显示完整页面而非弹框，排除空间工具；发现标明未来能力，示例讨论进入来源草稿。
- 新会话仅草稿、首条发送后加入历史、重命名、归档可达、受管只读、Executor 消息与 Worker 跳转。
- 320、360、390、414、768、1440px 无文档或主面板横向溢出；390px Fork 弹框处于可视范围，返回列表和进入详情正常。
- 主原型无 pageerror。桌面、手机信息流与手机 Fork 截图人工检查。
- 独立项目 HTML 排版切换、本地勾选保存、窄屏布局；直接 file: 的 JSON fetch 失败会保留摘要并解释原因。
- 补充验证跨机器投递明确区别于本机草稿，并保留已有目标会话标题。
- JSON 成功显示使用**受控 fetch 返回实际 project-data.json 内容**检查；不是对 GeneHub Preview 真实资源桥的端到端验证。桥能力依据 AssetPreviewPage 源码核对。带 allow-file-access-from-files 的 Chromium 仍拒绝 file: fetch，最初成功路径检查超时，保留这一限制，不将其计为成功；随后按上述受控方式验证页面成功呈现。

检查期间修正：跨机器投递到已有会话不应改掉原标题。另修正普通问题“按主题”被误显示为授权拒绝的提示。修改后重新执行主检查与补充检查。
