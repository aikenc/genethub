## 结论与用户场景

Human 已明确：GeneHub 面向用户自己机器上的高权限 Agent。经账号/设备认证且获准与完整 Agent
对话并驱动其工具的连接，等价于使用目标 daemon 所属 OS 用户。它应能操作该用户可访问的文件、
终端、Git、设置和其他项目。Session/标签记录来源与协作关系，不是平台内的角色等级。

例：手机上同一用户让 Agent 修改项目 B，工具能完成，直接会话/文件接口却以“跨项目”拒绝，
这是入口语义不一致。只封 RPC 不构成隔离；再补一层 Agent/project ACL 会扩大复杂度。

这个结论不包含未认证连接，不突破 OS 权限，也不把仅展示分享升级为 Agent 控制。
密钥输入、用户提问、只读/plan、来源标记仍是业务功能，不宣称能隔离同 UID 的恶意 Agent。
本次任务范围、开发工具权限、发布许可与提交审查不因产品全权而变化。

## 实施顺序与验收

| 顺序 | 改哪里 | 建议 | 业务验收 |
|---|---|---|---|
| 1 | `authz.rs`、local/hosted/device 入口 | 分清连接认证与连接内操作；将已认证完整连接归一到已有全权路径，保留真实 actor/session/device 身份，不新增 token 或角色框架 | 本地、配对设备、完整 hosted Channel 的同一操作结果一致；未认证/账号不匹配拒绝 |
| 2 | `router.rs`、会话控制 | 按最新合同重做 `e4d6aa35` 新增的跨项目 Human 限制；清理没有当前消费者的 PM/Workflow 特例，不把父子归属和幂等一起删除 | 同用户 Agent 可跨项目创建/发送/停止普通会话；团队协作与来源标记正常 |
| 3 | Files/PTY/Git/Settings 路径 | 统一普通完整连接的能力；目录映射、路径规范化和请求参数校验保留，不能把某 API 的拒绝当作对同 UID 工具执行的沙箱 | 同一连接经 Agent、CLI、直接接口完成相同任务；不要求换身份或复制凭证 |
| 4 | 分享、设备撤销、admission | 仅展示分享独立保留范围；凭证撤销和过期在原入口生效；relay/RTC 不凭载体增加权限 | 分享不能发送会话/执行工具、不能越过分享范围；撤销/过期连接停止操作 |
| 5 | 测试与文档 | 将旧细粒度拒绝测试逐项按新合同迁移，先建立成功路径和真实外部边界；不要只删断言 | 使用真实 artifact 验证上述场景；明确当前实现与目标差距 |

认证只需沿用现有证明，不以“全权”为由跳过握手、取消撤销/过期检查、混淆其他账号或获取其他机器的授权。
当前版本拒绝操作时保留错误，不切换 `LocalUser` 或读取 token 绕过；通过正常代码变更实现合同。

## 审计结论重分类

- 普通 Agent 有完整 Devices/Settings/Update/终端能力：符合完整 Agent 定位，不直接定为越权缺陷。
- 同 UID 程序可使用本地用户凭证：在该 OS 信任域内不能据此承诺 Human/Agent 强隔离，不继续堆软件角色。
- 默认完整执行邀请：取得它意味着机器账号级访问，应明确展示含义；不在本任务另建分级授权产品。
- 平台 Human 卡片/Provider 输入：保留用户交互意图，重新审视限制是否只服务明确流程，不把来源类型视为硬隔离。
- 日志泄密、未认证读取、分享越界、撤销/过期不生效：真实边界问题，仍须修复。
- 故障退出、数据损坏与持久化顺序：是可靠性问题，不能与权限加层混为一谈。

## 简化任务先收尾

1. 先修本轮新增的扫描取消标志不复位和浏览器孤儿清理路径，用已有资源所有权机制和故障回归证明。
2. 让 `evidenceStatus: invalid` 真正阻断对应退役验收；不能只改文字同时仍排除用例并报告全部接管。
3. 补齐 TS 并发场景（冷/热阶段、工具循环、观察客户端与详情/预览交互）及 Claude 子任务隔离。
   旧 Rust 与新 TS 的不同 SHA/artifact 必须如实记录；不为补收据新造通用 parity 框架或永久恢复旧 runner。
4. TS 接管验证与治理迁移完成后，移除 CLI 对旧 Rust helper 的依赖，删除活动 crate/占位注册/标签分支；
   历史 ID 与证据归档，不能把 94 个永不执行的占位用例当作正常测试工程的永久组成。
5. PTY、取消、原子保存、数据引用顺序等必要修复保留。对 30 秒检查点、逐 blob fsync、进程 census
   等具体设计分别说明失败场景、已有机制为何不足、写入/延迟成本与验收，不把所有审计发现自动纳入一个重构。
