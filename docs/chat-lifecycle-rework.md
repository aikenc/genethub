## 1. 业务承诺

会话组织历史；执行负责一次启动、运行和结束；客户端连接观察执行。
归档 round 可以跨越多次执行，不能充当停止某次执行的身份。

| 承诺 | 可验证的结果 |
| --- | --- |
| 接受明确 | 从占用会话开始就有可取消的执行责任；启动失败或被停止后不会留下稍后重新占用会话的任务。送达结果未知时不自动重发给 CLI。 |
| 归属明确 | 只有当前执行及其适配器实例能提交当前执行的事件；过期启动、停止、终态不会改写下一次执行的状态、正文或台账。 |
| 停止明确 | 停止请求与停止完成分开；启动阶段也能停止。结束前处理所属任务与进程，无法确认关闭时保留可操作错误及执行责任。 |
| 观察可恢复 | 同一 Client 经断线或 daemon 重启后，以新快照和对应游标恢复；重同步失败会再次尝试；旧订阅回调不能改写新订阅。 |
| 内容可恢复 | 正常退出保存已接收正文；进行中输出即使随后静默也有定时检查点；完成记录持久化成功后才删除检查点，恢复不得重复追加同一条正文。 |

现有 `session.send` 回复继续表示其既有交接结果。本轮不增加自动重试、自动续跑或外部工具副作用
的 exactly-once 承诺。明确重试是一条新的用户命令；结果未知时应先读取会话当前事实。

## 2. 基线上的具体缺口

1. `send` 的超时只结束等待；启动期间未安装到 `Live.agent` 的资源尚无统一取消入口。
   ACP 初始化前启动的后台任务可持有进程，`interrupt` 此时又找不到 agent。
2. 停止升级在外部等待后继续修改当前会话；围栏用 round 身份，覆盖不到同一 round 内的下一次执行。
3. 泵先 apply 终态，之后才在 `settle_round` 核验 turn；拒绝台账结算并没有拒绝状态变更与发布。
4. Client 对 reset 快照没有同步重置游标；重同步失败还会提前清掉待恢复标记。
5. 进行中保存依靠下一条事件触发，最后一批输出可能长期不落盘；chat 追加只 flush，随后就删除
   已 fsync 的检查点；写入失败时也会先取走待保存条目。

这些是代码边界上的待验证缺口。只有失败 run 或能检查的生命周期不变量支撑对应结论；
既有压力用例通过、没有复现某个猜测，均不扩大解释为所有交错安全。

## 3. 最小职责调整

### 3.1 一处管理执行归属

在每个 Live 内集中管理当前执行身份、启动/运行/停止阶段及取消责任。新请求与授权后的继续执行
使用同一套领取和结束规则。状态转换在同一串行边界内完成检查与改写；CLI 等待在边界外进行，
返回后重新按原执行身份提交结果。旧 round 台账继续承担归档职责。

终态、事件通道关闭、启动失败、停止升级和关闭会话共享结束入口。该入口负责一次性的状态、
台账、正文提交及发布；过期事件在进入这些副作用之前拒绝。逐步删除各路径独立写 Idle/Failed
和自行 flush 的分支。与会话执行无关的标题、选项和历史查询继续使用原有接口。

取消责任覆盖尚未完成 initialize 的启动任务。适配器持有其后台任务与进程的清理责任，原生
及 WASI 路径都需成立。停止使用执行身份，保留同一逻辑 round 继续运行的产品能力。

### 3.2 快照与游标共同恢复

初次订阅、缺口恢复和重新连接共用快照接纳规则：接纳快照时同步接纳它的 seq，reset 允许游标
降低；服务端识别超出当前序列范围的旧游标。客户端串行处理恢复结果，保留失败后的恢复需求，
以订阅及连接身份拒绝已失效的异步回复。快照应用后，旧 replay 状态不能覆盖快照中的较新状态。

优先复用已有 snapshot/seq/reset 契约。只有现有字段无法消除歧义时才扩展协议，并补混合版本
验证。快照描述当前事实，事件负责递送变化；连接退出不会取消执行。

### 3.3 明确保存的提交顺序

保留现有 chat/trunk 格式和 open-turn 检查点。用受执行生命周期管理的定时触发保存最后一批
输出；终态和退出先停止相关写入并等待完成，再做最终保存。chat 记录达到持久性边界后才清理
检查点。失败时保留待保存数据并给出错误，下一次执行不能覆盖尚未恢复的检查点。

进程崩溃恢复与机器掉电的保证分开记录。SIGKILL 测试不作为掉电持久性证据；文件提交顺序另做
代码和文件系统边界审查。恢复已有历史沿用当前语义，未完成执行不会自动重跑外部工具。

## 4. 验证矩阵

| 场景 | 控制点 | 独立事实 |
| --- | --- | --- |
| initialize 尚未完成时停止 | 外部 ACP CLI 暂不回答 initialize | 停止有界、原进程消失、迟到初始化不能复活旧执行 |
| 取消后继续同一 round | 外部 CLI 延迟原终态；新执行保持运行 | 旧停止升级不杀新进程，不改变新执行状态 |
| 终态与结束路径交错 | 外部协议响应、进程退出 | 正文不串轮，台账与客户端状态一致，下一条可以执行 |
| 同一 Client 重连 | 真实连接关闭后恢复 | 快照游标同步，后续事件继续到达，无持续 resync |
| daemon 重启后复用 Client | 真实 host 退出、相同数据目录重启 | 旧游标不会阻挡新事件，历史可读 |
| 最后一批输出后静默再崩溃 | 两批相隔小于保存间隔的文本，随后停止输出 | 重启后两批都存在；连续两次重启恰好一次 |
| 正常退出与保存失败 | 真实进程、磁盘写入/恢复边界 | 最终正文与检查点交接有明确结果，不静默清除恢复副本 |

业务测试由 testctl 的 TypeScript specialty/journey 驱动真实 host、guest、公开 Client、磁盘与
受控外部 CLI。现有受控 ACP 替身仅替换 CLI 协议对端，不能证明所有真实供应商行为；保留真实
CLI canary，缺环境或余额时如实 blocked/failed。默认模型场景仅替换公网 LLM endpoint。
不通过产品私有导入、隐藏配置或 test-only API 制造调度顺序。

先保存基线失败 run，再运行原用例复验；随后按影响面运行 change 和角色门禁。新产物记录 CLI、
host、guest 的实际 SHA-256，并绑定源码 tree 与测试 tree，补偿旧 runner 只标识薄 CLI 的缺口。
最终 gate 按原始结果报告；基线相同的失败不改写为 passed。

## 5. 范围与方案门

实现模式为 guest-only：daemon/adapter 与公共 Client；使用已有 host 进程能力，不扩展 WIT 或安装
协议。若实际复现证明必须改 host，先更新此声明并增加相应原生验证。

资产与执行留在资源机器；本机和远程 Client 使用同一协议。内核不按 agent 名称分支。第二种
执行形状为内置 stdio Agent 与 OpenCode HTTP/SSE；共享规则必须支持现有适配器差异。

外来事件仍经适配器归一化，受已有协议形状与体积限制；执行身份在内核入口核验。日志记录执行
关联、取消阶段、过期结果及保存错误，不记录模型凭证或完整提示词。

本轮范围不含静默判死、分布式工作流平台、通用事件溯源日志、自动重放工具副作用、跨升级无缝
续跑、诊断容量策略重做或无关测试迁移。
