# 测试规格

> MVP 全面落地后执行。  
> 核心原则：**一套用例，两种模式。** 全链路集成与真实模型 E2E 跑的是**同一份测试代码**，唯一区别是 LLM 后端接的是 mock 还是真实模型。  
> 用例全部**基于用户旅程**设计，不按模块切。  
> 上位文档：[architecture.md](./architecture.md)。

---

## 1. 为什么是一套用例

两套测试代码一定会漂移：集成套件慢慢变成开发者自娱自乐的模块测试，E2E 套件因为跑得慢而年久失修，最后两边都不可信。

所以只维护一份旅程用例，用一个开关切换后端：

```
JOURNEY_LLM=mock   → 每次合并跑，免费、确定、可注入故障
JOURNEY_LLM=real   → 每日 + 发版前跑，模型为 deepseek-v4-flash
```

**断言在两种模式下必须完全相同**。这条约束反过来强制了正确的断言方式：只能断言行为与结构，不能断言模型说了什么（见 §6）。凡是需要为真实模型放宽的断言，说明它一开始就写错了。

### 1.1 分层与门禁

| 层 | 内容 | 频率 | 门禁 |
|----|------|------|------|
| **L1 模块级** | 顺手写的往返/性质测试与回归钉子 | 每次提交 | 全绿 |
| **J-mock** | 全部旅程用例，LLM 为 mock，除此之外**所有模块都是真的** | 每次合并 | **全绿才允许进 J-real** |
| **J-real** | 同一批旅程用例，LLM 为真实模型 | 每日 + 发版前 | 发版门禁 |

顺序是硬性的。真实模型又慢又贵又不确定，用它来发现"WebSocket 没重连"是浪费。

### 1.2 为什么不设单元测试层

因为在 AI 写代码的前提下，**大部分单元测试是自证清白，不是验证**。

代码和测试出自同一个模型、同一份（可能是错的）假设。假设错了，测试会把错误一并固化下来然后变绿。它证明的是"实现和我对实现的复述一致"，而不是"实现是对的"。再加上 AI 倾向于把依赖全 mock 掉，跑的其实是一堆桩，真实的字段名、事件顺序、协议形状全被绕过去了——而那恰恰是 AI 最容易写错的地方。覆盖率在这种情况下是纯粹的虚荣指标。

真正的判据不是"单元还是集成"，而是：

> **这个测试有没有一个独立于实现的事实来源？**

旅程用例天然满足：真实进程、真实协议、真实磁盘、真实浏览器，它们不会陪着你的错误假设一起演。

按这个判据仍值得写的只有两类，归入 L1，不设覆盖率指标：

| 类型 | 事实来源 |
|------|----------|
| 往返与性质测试（编解码 round-trip、不变量、与参考实现差分） | 数学性质或另一份独立实现 |
| 回归钉子：旅程用例抓到真 bug 后补的最小用例 | 真实发生过的故障 |

## 2. 两种模式的唯一差异

**除 LLM 外的一切都是真的**：真的 daemon 进程、真的 relay、真的控制面、真的 WebSocket、真的浏览器、真的 agent 子进程、真的文件系统与 git 仓库、真的 PTY。

| | J-mock | J-real |
|---|--------|--------|
| LLM 后端 | 本地 mock 服务 | `deepseek-v4-flash` |
| 其他所有模块 | 真实 | 真实 |
| 用例代码 | 同一份 | 同一份 |
| 断言 | 同一套 | 同一套 |

### 2.1 怎么把 LLM 换掉而不改被测代码

两类 agent 用同一个办法的两种接法：

| Agent | 接法 |
|-------|------|
| 内置 Genet Agent | 模型配置里把 `baseUrl` 指向 mock 服务（与真实模式唯一的配置差异） |
| 外部 agent（OpenCode 等） | 同样把它的模型 `baseUrl` 指过去 |

这样连**内置 agent 也不走特殊分支**——不使用它内建的假 provider，因为那条路径在真实模式下不存在，会让两种模式的代码路径产生分叉。假 provider 只保留给 L1。

### 2.2 只有 mock 模式能做的事

这些是 mock 模式的**附加能力**，写成同一批旅程的额外分支，真实模式下自动跳过并记录跳过原因：

- **故障注入**：中途断流、429、500、超时、畸形 JSON
- **断言送进模型的内容**：system prompt、工具定义、消息历史是否符合预期
- **确定性的多轮编排**：精确控制"第二轮调用哪个工具"

第二条容易被忽略但很值钱：它验证的是**我们把上下文正确交给了模型**——真实模型反而看不出来，因为它会替你兜住错误。

### 2.3 Mock LLM 服务规格

一个小型 HTTP 服务，实现 `POST /chat/completions`（SSE 流式）：

- **脚本化**：每个用例声明每一轮返回什么（纯文本 / 工具调用 / 多轮工具调用 / 超长输出触发截断）
- **忠实还原真实 API 的帧形状**：`tool_calls` 分片下发、`reasoning_content` 与 `content` 分离、`finish_reason`、`usage`（形状以 §8 实测为准）
- **可注入故障**：见 §2.2
- **可回放**：记录收到的请求，供用例断言

帧形状必须对齐真实 API，否则 mock 会掩盖解析 bug——这正是我们在真实接口上实测过 §8 那几条的原因。

## 3. 主旅程

每条旅程是一个用例，在 §5 的矩阵里跨 agent 与模式重复执行。

```
1. 安装      在干净环境安装分发包，出现在应用列表
2. 首启      托盘出现，daemon 起来，主窗口可见
3. 初始化    「先体验」→ 临时用户 + 恢复密钥；机器出现在「我的机器」
4. 配置      设置页填入模型凭证
5. 会话      在浏览器里发一条需要动手的任务（如「读 README 并新建一个文件」）
6. 观察      流式输出、工具调用详情、diff 正常渲染；文件真的被创建
7. 鉴权      「登录并绑定这台电脑」走设备码授权，机器显示已绑定
8. 接力      生成一次性链接 → 在另一个浏览器打开 → 看到同一台机器与同一个会话
9. 退出      关窗后仍在线；退出后子进程全部结束
```

## 4. 分支旅程

每条都是完整旅程的变体，不是孤立的模块测试。标注 `[mock]` 的只在 mock 模式跑。

### 4.1 身份与接入

| 旅程 | 要验证的事 |
|------|------------|
| 跳过登录直接用 | 不登录也能跑完一条任务 |
| 临时用户升级为正式账号 | 机器归属、设备会话、审计一并迁移，不丢机器 |
| 一次性链接的四种结局 | 核销一次成功；第二次失败；过期失败；撤销后失败 |
| 撤销设备 | 撤销后该设备立即失效 |
| 机器被撤销 | daemon 不再重连；本地不残留登记信息 |
| 手机浏览器接入 | 窄屏布局可用，能发消息、能看工具详情 |
| 公钥指纹核对 | 首次连接显示指纹，与桌面端一致；指纹变化时告警 |

### 4.2 会话与 agent

| 旅程 | 要验证的事 |
|------|------------|
| 多轮工具调用 | 工具结果回灌后继续，直到收尾 |
| 切换 agent | 同一工作区从内置 agent 切到 OpenCode，历史可见、新会话正常 |
| 切换模型 / 思考档位 | 控件生效；不支持的 agent 不显示该控件（而不是点了报错） |
| 中止任务 | 停止按钮真的打断，落 `TurnCanceled` 而不是静默结束 |
| 审批通过 / 拒绝 | 拒绝后 agent 合理收尾且文件未被修改 |
| 无客户端在线时的审批 | 挂起并计时，超时按默认策略处理**且留审计**——断言"没有静默放行" |
| 未配置凭证 | 首条任务给出明确提示，不是静默失败或空白 |
| 第一次打开 | 没有项目时请他选一个（桌面弹原生选择器，浏览器收路径）；有项目没密钥时指到设置页；两样齐了才给「新建会话」。目录不存在时显示 daemon 的原话 |
| agent 未安装 | 该 agent 不出现在选择器，且不影响其他 agent |
| agent 子进程崩溃 | 会话进入错误态，daemon 存活，其他会话不受影响 |
| 未知工具类型 `[mock]` | 走 `Unknown` 兜底渲染，不白屏、不丢事件 |

### 4.3 工作区能力

| 旅程 | 要验证的事 |
|------|------------|
| 让 agent 改代码后看变更 | 变更面板列出改动，diff 渲染正确 |
| 提交 | commit 后变更面板清空，git log 有记录 |
| 浏览与编辑文件 | 文件树、预览、编辑保存 |
| 终端 | 开、输入、resize、关；输出正常回显 |
| 大输出 | 触发截断且明确标注 |
| 路径穿越 | 越出工作区的读写被拒绝 |

### 4.4 韧性

| 旅程 | 要验证的事 |
|------|------------|
| 断网重连 | 拔网再插，会话继续，事件不丢不重 |
| 回合中途掉线 | 客户端在回合进行中断开：回合照跑完，重连后按 seq 补回缺口且不重复 |
| 超出重放窗口 | 明确回全量快照，不静默半量 |
| 重启恢复 | **真的重启 daemon 进程**后，项目 id 与历史都在，且下一轮把重启前的对话交给了模型 |
| 从列表回到旧会话 | 关掉再从会话列表找回来，看到历史并能继续聊 |
| 机器离线 | 前端显示离线并给出可操作提示 |
| 三条通道 | 本地回环 / 局域网 / 转发层各自可用，且降级顺序正确 |
| 控制面短暂不可用 | 已建立的转发连接不受影响；新连接被拒绝而不是放行 |
| 撤销送达 | 机主撤销机器后，relay 通过订阅流收到并断开在线连接 |
| 契约漂移 | 两侧 wire 摘要不一致时构建失败 |
| 转发层不解析 payload | 喂畸形/加密帧照样转发不报错 |
| 模型接口故障 `[mock]` | 429 / 500 / 断流 / 超时各有明确的用户可见错误，不是空白 |
| 真实凭证被拒 `[real]` | 拿一个无效 key 打真实接口：落到可行动的错误码，文案里写的是用户配的 provider 名 |

`[mock]` 那一行注入的都是我们自己造的故障，它们证明的是同一件事——我们的分类逻辑接对了。真实接口拒绝我们时的状态码、响应体、头部长什么样，只有 `[real]` 那一行能证明，所以它不能被前者顶替。

### 4.5 桌面进程生命周期

daemon 是产品，窗口只是方便，所以这一组测的都是「窗口不在了之后」：

| 旅程 | 要验证的事 |
|------|------------|
| 接管遗留 daemon | 上一个外壳崩溃后留下的 daemon，被新外壳直接接管，端口与 token 一致 |
| 看门狗 | daemon 被硬杀后自动重启，新端口通过事件推给前端 |
| 主动退出不算崩溃 | 用户从托盘退出后，看门狗不把它再拉起来 |
| 干净关停 | 停机后 `endpoint.json` 与锁文件都不残留——残留即意味着它是被杀的，agent 没人收 |

## 5. 覆盖矩阵

| 维度 | 取值 |
|------|------|
| 模式 | `mock`（每次合并）、`real`（每日 + 发版前） |
| Agent | `genet`（内置）、`opencode`；`acp` 至少跑主旅程 |
| 旅程 | §3 主旅程 + §4 分支旅程 |

规则：

- **主旅程**：每个 agent × 每种模式都跑。
- **分支旅程**：默认在 `genet` 上跑全套；`opencode` 至少覆盖 §4.2 会话与 agent 那一组——那里才是 adapter 差异会暴露的地方。
- `[mock]` 标记的分支只在 mock 模式执行。

「同一批用例在两个形状完全不同的 agent 上都通过」，就是 [architecture.md](./architecture.md) §2 B3 的验收动作。

## 6. 断言纪律

两种模式共用断言，因此**只断言行为与结构，绝不断言文本**：

| 断言 | 不断言 |
|------|--------|
| 工具被调用了、参数合法 | 模型说了哪句话 |
| 文件真的被创建/修改成预期内容 | 输出的措辞、长度、格式 |
| 事件序列完整、状态机正确 | 调用了几次工具 |
| 有可见的流式输出（非空、递增） | 具体 token 数 |

任务设计成**结果可验证**的形式（创建指定文件、写入指定内容），断言磁盘状态而不是自然语言。

真实模式的额外纪律：网络类失败重试 1 次；**断言失败不重试**（重试会掩盖真问题）。

## 7. 安装与成本

**安装测试**（主旅程第 1–2 步的落地方式）：

| 平台 | 做法 |
|------|------|
| Linux | 干净容器里安装分发包，脚本驱动首启与自检 |
| Windows / macOS | CI runner 上装包 + 冒烟；无 runner 时至少每次发版手动过一遍主旅程 |

自检项：可执行权限、内置 agent 二进制可用、数据目录创建、**默认工作目录被建出来**（见 [daemon.md](./daemon.md) §4.2；这条决定了新装用户第一屏是聊天还是文件选择器）、单实例锁、卸载残留清理，以及**安装目录内不存在 `node` / `node.exe` / `node_modules`**（PC 端零 Node 运行时，见 [desktop-client.md](./desktop-client.md) §4.1）。

跑测试时用 `$GENEHUB_WORKSPACE_DIR` 把默认工作目录指到临时目录：任何一次测试运行都不该在跑它的人的 home 里留下文件夹。

外部 agent（OpenCode 等）由**测试环境预装**，不随分发包安装——这正是要验证的行为之一：装了就出现在选择器里，没装就不出现，且不影响其他 agent。CI 里装法是 `npm install --prefix ~/.opencode opencode-ai` 后把它的 `.bin` 加进 PATH；本地没装时相关用例跳过并打印原因，其余照跑。

**成本控制**（仅 J-real）：flash 档模型、提示词短、设 `max_tokens` 上限；记录每轮 token 消耗，异常增长要查。

## 8. 已实测的模型侧事实（2026-07-28）

写下来避免实现 mock 与 provider 时重新踩：

1. **默认开启思考**。不加参数时短 `max_tokens` 会被推理内容吃光，`content` 返回空字符串。用例要么设 `thinking: {"type": "disabled"}`，要么给足 token。
2. **推理内容走 `reasoning_content` 字段**，与 `content` 分离。不解析它就会丢掉全部思考内容。内置 agent 的 OpenAI provider 已支持（同时兼容 `reasoning` 命名）。
3. **工具调用是标准 OpenAI 流式形状**：首帧带 `id` 与 `function.name`，后续帧只带 `function.arguments` 分片，需按 `index` 聚合。
4. `usage` 带 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`，可用于观测缓存命中。

接口与密钥：OpenAI 兼容 `https://api.deepseek.com`（另有 Anthropic 兼容 `https://api.deepseek.com/anthropic`）；密钥 `DEEPSEEK_API_KEY` 本地放 `.env`（**已 gitignore，不得入库**），CI 用密钥托管。文档：https://api-docs.deepseek.com/zh-cn/

## 8.1 当前落地的套件

| 套件 | 位置 | 跑的是什么 | 需要什么 |
|------|------|-----------|---------|
| Rust 单元与集成 | `cargo test --workspace` | 协议、daemon 各模块、agent、旅程（daemon + agent + mock 模型） | 无 |
| 第三方 agent 旅程 | `testing/tests/opencode.rs` | **真实 OpenCode 进程**接同一个模型后端，事件归一化后进同一条时间线 | PATH 上有 `opencode`，否则跳过并打印原因 |
| relay | `apps/relay && npm test` | 帧转发、契约、边界检查、wire 摘要 | 无 |
| 工作台 | `packages/web && npm test` | 时间线、协议客户端、面板、宿主层 | 无 |
| **全栈旅程** | `packages/web/src/e2e/journey.test.ts` | **真实 daemon + 真实 agent + 脚本化模型**，用的是工作台自己的客户端 | `cargo build -p genet-daemon` |
| 跨栈配对 | 控制面仓库的 `test/pairing.test.ts`、`test/relay.test.ts` | daemon 自己走设备码配对，浏览器经 relay 连回来 | 同上 |

全栈旅程这一条是分量最重的：其他前端测试都把 socket 假掉了，而"事件发到了一个没人监听的 topic"在假 socket 下和"没有事件"长得一模一样。它上线的第一天就抓到了这个 bug。

第三方 agent 那条同样不能省。OpenCode 是唯一形状不同的 adapter——HTTP 服务加独立事件流，而不是 stdio 子进程；只有让它真的跑起来，才知道归一化层是抽象而不是内置 agent 的别名。它接的模型后端与内置 agent 完全一致（mock 模式下配置文件里指向 mock 服务，真实模式下指向 DeepSeek），因此两种模式共用同一份用例。

## 9. 工具选型

| 用途 | 工具 |
|------|------|
| L1 | 各语言自带 test 目标 |
| 旅程编排 | Playwright（驱动浏览器）+ 测试夹具拉起真实进程与临时目录 |
| Mock LLM | 自建小型 HTTP 服务，与用例同仓库 |
| 桌面壳 | Tauri 的 WebDriver 方案；不可用时退化为手动清单 |

硬性要求：**每个用例自建临时数据目录与端口，跑完清理**。共享状态的测试迟早互相干扰，排查成本远高于一开始就隔离。

## 10. 执行顺序

```
L1 全绿
 └─► 搭 Mock LLM 服务
      └─► 写旅程用例（主旅程 → 分支旅程）
           └─► J-mock 全绿 ──（有问题就地修，不挂起绕过）
                └─► 同一批用例切到 real 模式
                     └─► J-real 全绿
                          └─► 发版
```

J-mock 阶段发现的问题**就地修**。集成测试挂着不修，等于没有集成测试。
