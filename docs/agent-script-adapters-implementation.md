# 脚本 Agent 持久交互：首批实施记录

日期：2026-10-06。范围来自 [提案 §16](./agent-script-adapters-proposal.md)：优先落实 N1、N2/N3 的会话入口、N4 资源回收、N7 日志边界，以及 N8 的资源诊断部分。改动保留在 dev-0 本地，未提交、未发布。本记录不代表 N1–N10 全部交付。

## 实际行为

- Agent 动作通过 `ctx.ask(job, step, ...)` 先取得非秘密准备记录落盘的短确认，再退出任务并确认进程组及孙进程已停止；最后发 `request.suspend` 才展示。停止阶段崩溃保留准备记录，显示停止结果未知，不误报等待。等待不依赖原协程、RPC、CLI 或页面。
- 待答记录绑定已加载的适配器与 SDK 内容修订。代码改变后拒绝派发旧答案，允许不执行新代码地取消旧事项，重新加载后再按新修订确认。
- 回答先校验并持久标记消费，再通过 `action.resume` 派发新执行。普通答案可保留，密钥答案只传给新执行；外部结果未知时不盲目重放。损坏记录保留、阻止新动作，修复后可 reload。
- `session.ask` / `genet session ask` 和原生 `request_user_input` 接入既有 Session 持久暂停点：停止当前执行，保留 Session / 用户 round，Human 回答后恢复新执行，不提升会话权限。
- Codex 原生请求 ID 按每次 CLI 启动隔离，防止上游请求计数复用使旧问题重新出现。
- testctl 在创建隔离目录时登记所有者、worker、UID、启动身份、boot 和目录 inode；下次 run 核验失去所有者的资源后回收。活跃任务、未知归属目录和身份不确定的进程保留。
- Read-only 设备的 Agent 列表和推送去掉 CLI 日志及私有状态文本；Session 日志权限保留。
- 资源泄漏报告在强制清理前保存 PID 和脱敏命令片段，避免清理后丢失诊断身份。

协议及多步骤 SDK 规则见 [线协议](./agent-serve-protocol.md)。新 RPC 与 CLI schema 同步；旧 `ctx.request` 是兼容入口，仍不满足长期持久暂停合同，用户脚本需迁移。

## 已明确的能力限制

当前 Codex/Cursor 账号授权 CLI 没有停止后恢复的合同。账号登录卡片明确报告工作台登录尚不支持，不保活登录进程、不展示已失效的授权材料、不引入终端登录兜底。Codex API Key 登录使用真实 CLI 保存；已有外部账号凭据可以重新检查。这不等于手机内账号授权目标已通过。

自动孤儿恢复只以 Linux procfs 身份为证据；Windows/macOS 尚未取得对应实机结果。旧版没有所有者记录的遗留测试目录不会自动删除。
