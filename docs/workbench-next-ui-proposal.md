# UX 优化提案：专家页面、统一新会话与共享选择


> **当前有效方案（2026-09-07）**：以下 §0 汇总最近几轮已对齐的方向，并细化本轮布局建议。§1–§9 保留上一阶段设计与实施记录；与 §0 冲突时以 §0 为准。特别是“点击对象默认继续旧会话”“长按作为主要入口”“工具 Tab”“重复的新会话/详情面板”不再作为本轮目标。各阶段实现边界见本节末尾实施记录。

## 0. 当前 UX：单一专家页面（2026-09-07）

核对基线 Open `7831310` / Cloud `945e144`。本次只调整前端页面、选择与导航，协议及 daemon 不重构。

### 0.1 命名和边界

正式用 **专家 / Expert、团队 / Team**。专家有独立配置和多个会话；Cursor/Codex 等仍称执行引擎，底层 workspaceId、agentSpace、agentId 含义不变。小队页展示当前真实直属成员，不建立新的团队数据库或广播语义，不因为 Parent 关系而新增调度权。

### 0.2 单一专家页面

取消“概要 → 详情”的层级和重复身份项。页面标题直接用专家名，头像、返回和切换跨两行；名称较大，第二行展示实际启用的 Component 标签。姓名和标签过长时截断，完整配置在对应页内可读。

```text
[返回] [头像] 专家名称                         [切换]
              component tags
[会话] [组件] [目录] [小队] […]
────────────────────────────────────────────────
当前页签内容，独立滚动

推荐提示词 + 原 Composer（仅会话页）
```

- **会话**：最近 10 项、查看全部、搜索和归档。首次发送才创建 Session，推荐词只追加草稿。历史点击继续精确原会话，保留现有 Fork、多选、转发等能力。
- **组件**：直接启停、添加/更新、移除现有组件；继续使用 revision 校验、Builder 校验及原有组件依赖约束。错误在表单明确呈现。
- **目录**：完整 Roots、code-workspace 添加目录，以及文件、变更、终端和宿主作用域工具。没有虚构 removeRoot RPC；单目录专家不显示不支持的多 Root 编辑入口。
- **小队**：直属成员平面列表，点击进入成员页面；已有专家加入、移出及上级关系配置采用现有 setParent。成员候选排除会形成环的对象，服务端仍是最终校验者；配置未注册的对象需要先完成组件配置。
- **…**：导入会话、资料与头像、文件、变更、终端。资料仍显示在当前页面内容区，不再另起详情层级。对象选择与目录选择可用短浮层，完整页面不使用窄弹框。

全局导航保持会话、专家、发现、设置。设备切换和系统设置属于设置；文件/变更/终端属于当前专家。没有长按唯一入口。

### 0.3 导航与草稿

页签与菜单子视图切换只替换当前历史状态；不会生成返回项。切换专家替换当前专家页，只有进入子专家建立父子返回链，并恢复父页签。创建/继续会话使用会话列表式返回目标，不让用户逐个退出专家页签。

专家项、新会话和聊天头部进入同一个专家页面。每位专家恢复自己的本地草稿和附件，不跨专家复制；切页签不会清掉输入。原 Timeline 与 Composer 继续复用；会话区 Composer 采用占位布局，不遮挡历史和推荐词。

### 0.4 可复用列表与专家选择

主目录和选择器共用 AgentList / WorkspaceRow / AgentAvatar：头像、名称和次要信息两行，按可靠最近活动时间排序。ExpertPicker 封装搜索、专家分组筛选和两行列表，不显示行菜单、不管理分组，可在其他需要选专家的入口复用。分组管理仍只在专家目录。

会话分组来自所属专家；主列表默认不显示受管/子专家内部会话，显式范围可访问。头像右上角状态和已读逻辑沿用现有实现。筛选不依赖当前可见 10 项；长列表滚动不带走导航。

### 0.5 已有协议盘点与微调范围

依据：[RPC](../packages/proto/src/rpc.rs)、[Session list/history 实现](../apps/daemon/src/session/manager.rs)、[文件树](../apps/daemon/src/files.rs)。下表是本轮基线事实，不是待实现功能清单全部必做。

| 查询 | 当前能力 | 处理建议 |
| --- | --- | --- |
| session.list | workspaceId/includeArchived，全列表 | 高优先级设计游标分页及匹配筛选；不是简单截取前10项 |
| session.get / subscribe | recentRounds；get 支持 beforeItemId | 已有最近轮次窗口，继续复用；get 的 beforeItemId 配合 recentRounds 使用 |
| session.narrative / session.rounds / round.trunk.list | cursor + limit | 已分页，不重复设计 |
| session.flow | 完整执行快照及消息 | 长流程需增量/分页；首版继续使用现有流，不另造固定 PM 管理 UI |
| workflow.history / session.importList | limit，无连续游标 | 数量限制不等于完整分页，按需要补续读 |
| workspace.list / agentSpace.children | 完整列表 | 根据对象数量决定是否补分页，不作为本次布局的必需条件 |
| directory.list / file.tree | 无同级游标；tree 有深度及安全数量上限 | 大目录横向分页是独立缺口，安全上限不能充当下一页 |
| 执行引擎目录、设备、进程等 | 小集合或状态快照 | 不为形式统一强行分页 |

`session.list` 目前先 list_meta 全量读入后筛选；返回 limit 只能首先改善传输，不能据此宣称磁盘扫描有界。会话分页微调需明确：服务端先筛选/排序、稳定游标与 ID 去重、nextCursor/hasMore、活动时间变化后的刷新规则，以及旧数组回包的兼容方式。字段名字和回包形式在实施前冻结，本文不指定未经验证的新 RPC 名称。

分组和已读包含前端状态：不能未经协议核对就要求 daemon 按本机未读直接筛选。受阻/运行总数也不能取本页长度；概要会话数需有全范围事实或诚实省略。优先复用既有摘要，若补轻量计数/范围查询须单列权限、计算成本与旧端降级，不订阅全部 Session 来凑数字。

最近10个 Session 摘要、最近10个业务 round、可视区 DOM 窗口是三个独立预算。首屏/历史窗口已实现的部分见 §9，不能在本轮重复描述成全部待新增。阅读锚点、顶部插页、新消息不抢滚动、迟到响应隔离、媒体预留尺寸仍需按真实场景验证；分页不能独自消除卡顿/跳变。

本轮采用统一专家页面、共享选择器和既有配置组件；前端导航改动不需要新的 RPC。

不重建 Session、运行 owner、授权生命周期、存储模型或连接机制。多设备默认互联仍延期；机器继续是操作边界。项目自定义 UI 沿用公共 HTML Preview；HTML 读取相对文件不等于获得 daemon 调度权，不新增固定 PM 工作流后台。

### 0.6 本轮验收与范围

验证单一身份栏、页签不增加 history、切换不堆栈、子成员逐级返回、新建/继续会话返回列表、独立草稿恢复、选择器分组生效、目录写入真实 code-workspace、配置拒绝可见，以及 320/390/1280px 控件可达。

最近 10 项仍是前端展示窗口，session.list 完整摘要和分页边界见 §0.5；不宣称已有端到端分页、计数或索引改造。保留原授权、执行生命周期、公共 Preview、Fork 和多选合同。多设备默认互联继续延期。

### 0.7 专家交互修订与添加入口（2026-09-07，覆盖前述同类细节）

- 专家目录点入后仍属于“专家”Tab；打开已有会话或真正发送后才进入“会话”。页签不入栈，子专家保持逐级返回。
- 移除“继续已有话题 / 查看全部”占位行。“查看全部会话 / 最近会话”切换放在专家的 … 菜单。
- 所有单选专家入口（切换专家、小队成员、上级关系、会话按专家筛选）共用 ExpertPickerDialog：全局弹框、同一两行列表、搜索及分组筛选，无行菜单。分组编辑的多选仍是专用成员编辑表单。
- 点击头像直接选头像，点击名字修改名字；头像继续是浏览器个人偏好，名字由 workspace.rename 持久化。右侧切换用于选择另一位专家。
- “全部”是取消分组限制，不是一个名叫“未分组”的分组。会话列表显示“全部会话”，专家列表/选择器显示“全部专家”；其余状态、归档和受管会话过滤继续生效。专家搜索以头部图标展开，默认不占第二行。
- 移除父专家时，客户端根据最新 workspace.list 计划后代集合，并以 session.list 检查整组运行/等待状态。确认后按叶到根调用既有 workspace.remove；保留每次服务端检查、文件、会话与 tombstone。它是可停止的顺序操作，不是新增原子批量协议；中途冲突时同步已完成结果并明确报错，不继续扩大移除范围。
- 添加入口修复：全局只挂载一个处理 dialog=open-workspace 的目录选择器。所有添加按钮指向该入口，完成后进入返回的专家页面；取消不创建登记，失败继续留在选择器显示原因。

**添加专家的下一步设计建议**

当前本质是把一个工作目录登记为专家；选择目录不等于已经配置了专业角色或搭好团队。下一版应做一个短的创建流程，沿用现有协议：

1. 入口叫“添加专家”，先提供“使用已有目录”和“新建工作目录”，并明确当前设备。已有 .code-workspace 属于第一项。
2. 选定工作范围后，展示名称、头像与 Roots 摘要。名称给合理默认值，可当场修改；重复打开已有目录则直达原专家，明确提示“已存在”。
3. 点击确认后进入专家页面并聚焦会话输入框，可直接告诉专家目标。组件/角色属于按需配置，不强迫用户先理解 Builder、PM、Executor。
4. “从模板创建团队”作为独立可选入口，复用现有 Pack 计划和 Human 授权。不能把一次添加目录包装成已完成团队初始化，也不能把工作流固定在 GeneHub UI。

本轮修复现有目录选择入口，不额外实现模板商城、后台推荐服务或新的专家数据模型。

## 1. 决策摘要

下一版整体重设计导航与交互状态，复用已有信息流、Session、授权、Fork、文件预览和 Agent 运行能力。采用微信式“列表进入聊天、返回列表”的使用方式，让用户管理会话与项目，不必管理已打开的聊天标签。

- 旧、新版本源码可以同时存在；新版本切换后只有一个正式入口。旧界面归档到构建范围之外，只供参考，不维护兼容运行入口或双版本开关。
- 归档的是被替换的外壳。继续使用的协议客户端、信息流、公共预览、语音和操作组件保留在活动源码中，不以“旧版”名义全部迁走。
- 参考微信官方 **WeUI** 的基础视觉和控件，复用可用样式；GeneHub 自己负责会话状态、导航、权限与跨机器上下文。WeUI 不是微信客户端源码。
- 保留四个一级入口：会话、空间、发现、工具。手机一级页展示底部导航，进入详情后展示返回；桌面默认导航、列表、内容分栏，不再强制展示聊天标签条。
- daemon/RPC 可以按需微调，但每项必须有对应交互缺口、旧端降级和可验证边界；不重建 Session、工作流引擎、订阅或授权生命周期。
- 项目管理页面由项目 Agent 在人的协同下设计。GeneHub 提供公共 HTML Preview 和反馈，不提供固定 PM 工作流管理后台。

本提案替代第四版中“继续保留用户可见多标签”的安排，以及“以旧外壳开关回退”的安排；第四版中的原生操作、空间工具作用域和公共预览边界继续适用。[第四版依据](../prototypes/team-mobile-workbench-v4/README.md)

## 3. 旧代码归档与新入口

### 3.1 目标目录

以下目录为建议结构，本次不会创建或移动：

```text
packages/workbench/
  deprecated/
    workbench-v4/
      README.md             # 基线SHA、替换清单、归档原因、活动组件映射
      reference/            # 已退休的外壳及必要参考样式/示例
  src/
    index.ts                # 对宿主保持单一公开入口，App 导出不变
    app/                    # 新外壳、路由、页面栈、响应式容器
    ui/                     # WeUI样式适配、GeneHub基础控件
    session/                # 活动信息流、操作、会话数据与草稿
    workspace/              # 空间浏览、详情及作用域
    preview/                # 活动公共预览
    protocol/               # 活动协议客户端
    ...                     # 语音、宿主、设备等现有能力
```

不能把旧版本简单移到 `src/deprecated/`：当前 Workbench tsconfig 的 include 为 src；Workbench 和 Cloud Tailwind 都扫描 Workbench src。放在其中仍会被类型检查、样式扫描，甚至被错误导入。仅设置 tsconfig exclude 也不能阻止活动代码主动 import。

归档要求：不进入 Vite 入口、TS 编译图、Tailwind 扫描、测试自动发现或发布包；活动源码不得导入 deprecated。发布打包范围单独核对，源码留在 Git 不等于要随应用发行。[包入口](../packages/workbench/package.json)、[编译范围](../packages/workbench/tsconfig.json)、[样式扫描](../packages/workbench/tailwind.config.js)

### 3.2 迁移方式

1. 固定归档基线、记录 Open/Cloud SHA 和逐文件归属。Git 保留完整旧版；参考目录只保留对理解旧设计有价值的已退休实现，不复制 node_modules、dist、数据和凭证。
2. 先将仍需使用的 WorkspaceRow、RecentSessions 等从旧外壳提取为活动组件，解除 import 依赖；当前 WorkspaceBrowser 直接从 Sidebar 引用它们，不能先移动 Sidebar 再补洞。
3. 在新 app/ 中实现导航和页面，但继续调用同一套活动能力。不要复制整个 store、TimelineView 或 Preview 形成两套维护分支。
4. 新入口达到替换门槛后，调整现有 App 导出指向新外壳，同时归档被替换文件。迁移中的未接线代码可以在分支中存在，生产路由始终只有一个入口。
5. 旧 UI 专属截图/布局断言可以随归档保留作参考；能力、协议、恢复和权限回归继续有效，按新入口调整验证方式，不因退役 UI 一并删除。
6. 回退通过部署前一组已验证的双仓产物/提交完成，不通过公开“旧版入口”。如发生数据迁移，必须先定义旧版可读性，不能把前端回退假定为数据回退。

因此，“两份源码并存、旧版无入口”可行；“两套完整运行时并存并相互引用”不属于本方案。

## 4. WeUI：复用什么，怎样接入

WeUI 官方将其定义为移动 Web 基础样式库，提供按钮、列表单元、对话框、进度、Toast、ActionSheet 等。主包入口为 CSS，并非完整 React 聊天应用。[官方说明](https://github.com/Tencent/weui/blob/master/README_cn.md)、[包定义](https://github.com/Tencent/weui/blob/master/package.json)

| 来源 | 复用内容 | 本项目承担的工作 |
| --- | --- | --- |
| WeUI | 列表单元、按钮、徽标、搜索、表单、加载、Toast、ActionSheet、Dialog 等基础样式与结构 | 封装受控 React 控件，接主题、键盘/焦点、触屏和桌面适配 |

WeUI 源入口包含 reset 和全局样式，不能直接在现有 Tailwind、Markdown、代码编辑器和终端上全量覆盖。导入顺序、CSS 变量映射和作用域必须显式确定；主题沿用 GeneHub 的亮/暗色和字号能力。项目 HTML 不强制注入宿主 WeUI，仍由项目决定页面样式。[源样式入口](https://github.com/Tencent/weui/blob/master/src/style/weui.less)

官方 README 列出 react-weui 和 weui.js 扩展，但不能据此假定它们适配当前 React 18。本轮核对 react-weui 上游 package.json：依赖 WeUI ^1.1.0，开发依赖 React ^16.9.0，peer 范围为 React >=16；这个范围不能代替在本项目 React 18 中的兼容验证。[包装库依据](https://github.com/weui/react-weui/blob/master/package.json) 首版不将这些包装库作为必需依赖；若选用，应核对锁定版本的 peer dependencies、事件/DOM 所有权和真实编译结果，不把旧示例直接搬进 Store。

WeUI 官方标注 MIT，许可文件还列明所含第三方组件的许可。落地时保留适用版权与许可说明，记录实际引入的版本和源文件；不复制微信品牌资源，不改变 GeneHub 自身的许可证。[上游许可](https://github.com/Tencent/weui/blob/master/LICENSE.txt)

## 5. 完整交互合同

### 5.0 核心业务关系：一个联系人，可以有多段独立会话

本版采用用户指定的微信联系人/会话心智作为设计参照，不试图复刻微信所有产品形态。关系上的主要差别只有：**一个 Space 可以拥有多个 Session**。在每个 Session 内，进入聊天、发送、等待回复、阅读历史、返回、未读和草稿尽量遵循同一套聊天习惯。

```text
机器：连接与操作边界
  Space：联系人式入口，代表共同的项目/工作上下文
    Session A：独立聊天历史与任务上下文
      round 1、round 2……：聊天中的任务轮次
    Session B：另一段独立聊天历史与任务上下文
  关联 Space：另一个联系人式入口，有自己的 Session
```

| 概念 | 用户理解 | 业务约束 |
| --- | --- | --- |
| Space | 我在和谁/哪个项目上下文交流 | 有名称、说明、角色/Component、文件和工具；不是一段聊天记录 |
| Session | 与这个 Space 的一段独立会话 | 属于一个 Space；有独立历史、草稿、阅读位置、运行配置和状态；不能只靠标题识别 |
| Agent | 这个 Session 采用的执行者 | 使用现有 Agent 绑定与能力；不取代 Space 的联系人身份，也不另造“好友”对象 |
| round | 一次用户任务及后续执行 | 一个业务 round 可以跨多个 adapter turn；完成一轮不关闭 Session |
| 消息/工具/执行事件 | 会话内的内容与过程 | 不等于新 Session；流式 token、心跳也不等于一条新聊天 |
| Parent、managed、Fork lineage | 空间归属、协作来源、会话来源 | 关系各有事实来源；Parent 不是群成员，managed 不是群聊，Fork 不改变原会话历史 |

联系人只是 UI 心智：保留 workspaceId、sessionId 和现有权限，不新增通讯录数据库、不把空间转成自然人账户。Agent 执行、Human 授权、受管只读是聊天中的业务能力；它们不应让用户重新学习一套标签导航。

**两个列表各回答一个问题。** “空间”列出联系人式 Space，解决找谁；“会话”列出独立 Session，解决继续哪段聊天。一个 Space 的两个 Session 在会话列表中就是两项，不能聚合成一个 Space 行后再要求用户每次挑选，也不能把二者消息合成一条历史。空间资料页可以提供仅属于该 Space 的会话列表。

例如同一“游戏项目”同时有“玩法讨论”和“发布排查”：列表显示两项，以 Space 图标/名称建立共同身份，以 Session 名称区分话题；各自显示最近内容、时间、草稿和状态。聊天页标题为 Space 名称，副标题为 Session 名称；手机标题不再变成“已打开标签”下拉。会话信息页仍可查看所属空间、执行 Agent、来源及运行配置。

### 5.0.1 进入与默认继续规则

| 入口或动作 | 明确结果 |
| --- | --- |
| 点击全局会话列表的某一项 | 打开该 sessionId，不因所属 Space 有更活跃会话而换目标 |
| 点击 Space 联系人条目 | 打开资料页，展示“继续会话”“新会话”“会话历史”和空间工具 |
| Space 的“继续会话” | 优先用户在本机上次访问的、仍存在且可进入的未归档 Session；无记录时选择最近有内容活动的可进入 Session。按钮旁显示选中的会话名 |
| 只有一段会话 | 直接继续它，不额外弹出选择器 |
| 有多段会话 | 主按钮继续明确的一段；“会话历史”可进入任何另一段，不维护一个可变的服务器“默认 Session” |
| 没有可继续会话 | 主按钮变为“开始会话”，进入本地草稿；支持新建与否由空间/Agent实际能力决定 |
| 显式“新会话” | 创建独立本地草稿；首次发送沿用现有创建/发送流程，Session 创建成功即按真实状态加入列表；发送失败保留草稿与失败提示，不假定创建和发送原子完成。不因为有未读/运行中的会话就拒绝新建 |
| 存在未发送新会话草稿 | 在空间资料页单独显示“继续草稿”；不悄悄覆盖已有草稿，也不把草稿当已创建 Session |
| 深链、搜索结果、通知、Worker链接 | 保持精确 sessionId/消息位置；失效时说明原因，提供返回空间，不静默进入另一段会话 |
| 受管只读 Session | 显示“查看会话”；可阅读不代表可发送。空间能否新建会话单独依现有规则判断 |

上次访问记录属于本机导航偏好，不因后台收到消息而改变。最近内容活动时间尚未有准确投影时，可暂用现有更新时间排序，但要承认重命名等也可能改变顺序；不能因此改变已确定的“继续会话”目标。归档会话从默认继续候选中排除，仍可从已有归档入口查找。

### 5.0.2 多 Session 带来的必要区别

- **共享项目，不共享聊天。** 同一 Space 的 Session 使用共同的空间文件/工具上下文，但聊天历史和草稿独立。并发会话对共享文件的修改仍是现有项目并发问题；UI 展示运行状态，不承诺每段会话拥有隔离文件副本。
- **状态属于 Session。** 未读、待回应、失败、运行中不能只挂在 Space 上。Space 资料可汇总“2 段会话有新内容、1 段待处理”，进入一段不能清掉其他 Session 的标记；没有可靠消息计数就不显示精确未读条数。
- **返回属于页面来源。** 从全局会话列表进入，返回原列表；从 Space 会话历史进入，返回该 Space 的历史；从项目页面进入，返回项目页面。返回不停止、不归档、不删除 Session。
- **回复始终有明确目标。** Composer、授权决定、文件反馈、转发都绑定精确机器和 Session。仅知道 Space 不足以执行“向某会话发送”；必须选择已有目标或明确创建新草稿。
- **会话继续不等于任务重启。** 一轮任务完成后仍留在同一 Session，可以继续交流。停止只作用于明确的执行；离开聊天、关闭预览、后台缓存淘汰均不是停止。
- **Fork 是显式新会话。** 按既有原生 checkpoint/历史重建合同生成新 Session，保留来源关系；不是打开同一会话的另一个标签，也不必然属于原 Space。
- **空间关系不改写会话身份。** Parent 或角色调整不能隐式复制/合并 Session，多个 AgentSpace 也不自动组合成群聊。资料页只展示真实关联关系。

### 5.1 一级页和返回

| 一级区域 | 内容 | 详情页面 |
| --- | --- | --- |
| 会话 | 当前机器会话，搜索、需处理筛选、草稿与未读提示 | 聊天、会话信息、历史搜索/来源 |
| 空间 | 联系人式列表、搜索；一项一个 Space；关联空间从资料页进入 | 资料、继续会话、新会话、会话历史、文件、Git、终端 |
| 发现 | 首版明确空态；未来来自空间的建议及依据 | 来源讨论，不伪造后台已生成的建议 |
| 工具 | 全局/机器级入口；由宿主提供账号、设备、设置、反馈等 | 独立工具页，顶部明示作用机器 |

手机：一级 Tab 切换恢复各自页面位置；进入聊天、文件、工具详情后隐藏底部 Tab，顶部提供返回和当前名称。返回次序为关闭短操作 → 返回当前详情的来源 → 所属一级页。浏览器返回与按钮使用同一份路由状态；深链没有来源时回到所属区域，不误退出站点。先适配系统/浏览器返回，不自行拦截边缘手势制造第二套历史。

桌面：保留一级导航和列表，右侧展示详情。需要的文件、终端可以作为空间工作面，默认不再混进聊天标签条。切换内容不会停止后台任务；停止、归档、移除和删除必须保持不同动作与既有语义。

机器是操作边界。页面状态、草稿、阅读位置、预览来源和工具实例都带机器身份。切换机器后不显示上一台的可操作内容；目标离线时显示真实连接状态。

### 5.2 会话列表、草稿和未读

- 会话列表一项对应一个 Session；第一行显示可区分的 Space/Session 名称与时间，第二行显示最近内容/状态摘要。受管、只读、导入或 Fork 来源通过紧凑标记与详情呈现，不能再次把名称挤掉。
- 分开显示“有未读内容”“等用户回应”“执行失败”“运行中”。需处理红点不会仅因打开聊天而消失，必须以问题解决或状态变化为准；运行时间长不自动判失败。
- 已读只在页面前台、相应 Session 实际可见并达到规定阅读位置时推进。停在历史处不能把后续全部消息标已读。列表 mounted、activeSessionId 未清理、后台轮询都不是阅读证据。
- 草稿以机器+Session 为键；未发送新会话使用独立本地 draft ID 和 workspaceId，不提前创建服务器 Session，也不能让所有新会话共用一个文本槽。
- 保存文字、附件引用和转发草稿；不把大文件/base64写入 localStorage。首版用现有附件能力与明确的失效状态，文件引用无法恢复时要求重新选择，不显示“已恢复”假象。持久大附件的存储另行核对。
- 保存阅读锚点（稳定消息/回合标识+相对偏移），不用绝对 scrollTop 作为唯一位置。数据裁剪、历史尚未加载或锚点失效时，显示恢复结果与降级位置。

### 5.3 消息流与操作保全

| 能力 | 本版规则 |
| --- | --- |
| 普通 Agent 信息流 | 复用 TimelineView/timeline 数据与未知工具呈现；继续保留用户消息、流式文本、工具、图片、历史和回合统计 |
| Executor 信息流 | 使用 session.flow 持久执行消息；既有 Worker 链接和证据可达；不替换成固定 PM 看板 |
| 手机长按 | 打开已有消息操作的菜单；与文本选择、滚动不冲突，桌面键盘和菜单也可操作 |
| 多选/复制 | 复用 selection/selectionCopy、范围与数量保护；反馈剪贴板失败 |
| 转发 | 保留可见历史、附件和预算规则。本机草稿与跨机直接投递按现有 controller 区分；跨机按钮明确提示将投递，不能画成保存草稿 |
| Fork | 沿用机器/空间/Agent/catalog 选择和原生 checkpoint/历史重建条件；入口明确“从此回合分支”，不把任意单条消息当完整 checkpoint |

“长按菜单”“新的列表”和 WeUI 控件都只是现有操作的新入口，不能偷偷改变 operation 的作用范围或投递语义。

### 5.4 最近 10 轮与稳定阅读

“默认最近 10 个对话”在实现中定义为最近 **10 个业务 round**，包含各轮用户输入与可见回复摘要，不是 10 条工具事件或 10 个 adapter turn。若最新一轮仍在运行，它占一个名额；当前状态和所有待处理请求独立返回，不受历史窗口截断。未分配到 round 的导入/旧格式内容需定义稳定分组或保留有界的兼容窗口，不能直接丢弃。

当前已有 session.rounds、session.narrative 的游标分页和 round.trunk.list/get，但打开 Session 的 subscribe 快照仍收集叙述内容和全部 round 摘要；现有历史分页不等于首屏已经只拉 10 轮。[读取与快照实现](../apps/daemon/src/session/manager.rs)、[RPC定义](../packages/proto/src/rpc.rs)

目标读取合同：首屏为最近 10 轮的有界内容/摘要、历史游标、当前状态和订阅边界；上滑接近顶部按同一历史边界加载更早 10 轮。历史页与实时事件使用稳定 ID 合并去重；新回复到达不让历史页跳号。断线补偿保留已加载窗口和阅读锚点，不能每次重连退回最新页或把窗口外缺项当删除。

轮数限制还需配合字节预算。超长一轮的正文、工具和图片不能无条件全量展开；保留摘要与加载完整内容入口。历史分页只影响浏览，不改变 Agent 上下文、Fork历史选择或转发内容范围；转发/复制未加载详情时仍走现有补全和预算规则。

性能与稳定性措施：

1. 先展示正确的会话标题、状态和已有缓存；缓存明确待刷新，不用旧会话内容顶替新目标。
2. 区分首次定位、恢复阅读、跟随底部、查看历史四种行为，统一滚动控制，避免输入框高度变化和 ResizeObserver 反复争抢位置。
3. 向顶部插入历史前记录可见消息及相对偏移，完成布局后恢复；图片预留尺寸，延迟正文展开保持锚点。
4. 按 Session 保存阅读状态；翻历史时新内容提供提示，不强制贴底。快速切换的迟到响应不得覆盖当前 Session。
5. 首屏分页后再按真实渲染成本引入虚拟列表/窗口回收。保留消息选择状态与数据，不能把“不在DOM”误认为“不存在或不可转发”；缓存和DOM均需有上限。
6. 测量点击到首个可读内容、冷/热打开耗时、快照字节、主线程长任务、DOM规模和阅读锚点偏移。先区分网络、daemon冷读、解析、渲染和布局成本，再确定优化目标；不把某次卡顿直接归因于组件库。

daemon 也需核对冷打开是否整文件读取和整份克隆。若底层仍线性扫描，可先改善回包和浏览器成本并报告剩余限制，再评估轻量定位/缓存；不要借分页立刻重写持久层。不能用前端 slice 最后 10 轮宣称端到端分页已完成。

## 6. 项目 UI 与公共 Preview

PM、WorkflowManager 和其他项目 Agent 可在人的协同下设计流程及其页面。Pack 提供起点；项目副本由项目维护，不因为模板升级覆盖用户修改。能执行的流程仍受当前 Workflow 合同约束，UI 重设计不承诺任意新调度语义。

首阶段沿用：Agent 读取现有事实 → 写入项目 HTML/相对 JSON → 会话链接或文件入口打开 Preview → 用户经公共反馈回到会话。页面可做筛选、排版、说明和本地交互；必须区分数据生成时间、本地状态和真实执行状态。GeneHub 不把项目自己的数据格式升级为统一的“产物/看板/流程管理”协议。

公共 Preview 保留路径解析、资源访问、截图/录制等既有能力。关闭后返回来源，反馈使用已有来源/目标选择和上传流程，不假定都是 PM 项目，也不强制退回来源会话而删除现有选择目标能力。

相对 JSON fetch 能力不等于页面拥有通用 daemon RPC。首版真实变更仍回到会话执行。若后续确需 HTML 请求打开会话/追加草稿，定义受限宿主消息合同，验证页面来源、机器/空间、目标资格和大小；不借通用 RPC 桥绕过 Human 授权。此扩展不作为首版依赖。

WorkflowManager 的 Parent 修正及已有团队迁移是独立项目模型工作；本版继续呈现真实关系，不通过隐藏或重画关系冒充迁移完成。

## 7. 状态归属与允许的协议微调

| 状态 | 归属 | 首版策略 |
| --- | --- | --- |
| Session、运行、Human决定、执行事实 | daemon 既有持久状态 | 沿用，不新增并行 Session/任务模型 |
| 当前页、来源、弹层、滚动、输入焦点 | 前端页面状态 | 统一路由；支持原深链；短操作不单独建立业务状态 |
| 草稿、阅读锚点、已读位置 | 首版本机前端存储 | 机器+Session隔离；版本化存储与失败降级；不承诺跨设备同步 |
| 连接、订阅、快照缓存 | 现有 client/Store owner | 保留有界缓存与订阅，不逐个订阅所有会话来补列表摘要 |
| 项目 HTML、页面数据 | 项目文件 | 使用公共 Preview；格式属于项目 |

### 微调预算

| 项目 | 建议范围 | 兼容与验证要求 |
| --- | --- | --- |
| 首屏/历史窗口 | 给现有订阅快照补可选窗口请求、历史游标及一致性边界；优先复用 round/narrative 读取，补齐窗口内容映射 | 默认最近10轮并设字节预算；旧客户端保持兼容；当前运行/待授权状态完整；分页与实时重放不重复不漏项；不默认重写存储 |
| 最近消息摘要 | 在 SessionSummary 增加一个可选摘要投影；候选内容为预览文本/类型、消息活动时间、稳定内容游标，名称待协议评审 | 不含工具大输出或隐藏推理；限制长度；来自持久可见事实。不要为每次 token 更新列表；旧记录可缺省，不启动全库回填 |
| 未读边界 | 先核对现有序号能否稳定表示“可见内容”；若不能，与摘要投影一起定义内容游标 | 不把连接流序号、心跳、rename、status更新时间当消息。历史导入、重启、fork、重放都验证；无可靠游标时不显示精确未读数 |
| 授权后状态 | 若快照仍不能恢复“决定接受/等待续跑”，可追加最小可选 interaction 展示字段 | 只投影现有持久事实，查询与事件一致；不改授权生命周期，不用前端推断正在执行 |
| 路由/工具归属 | 前端路由与现有 ExtraTab.scope 适配 | 不增加 daemon RPC；旧会话/预览链接和宿主扩展仍有效 |
| 置顶、免打扰、跨设备已读/草稿 | 本版不作为必需项 | 若要统一同步，独立设计偏好持久化，不能以几个 UI 字段暗中增加账号服务 |
| 自动发现、HTML调度、Flow实时页桥 | 延后 | 不属于本次微调，不加入常驻扫描、通用RPC桥或新的工作流服务 |

每项协议微调单独列出字段、事实生产者、持久来源、权限过滤、事件/快照一致性、旧端降级和必要生成代码。新增可选字段不自动证明兼容，仍需验证编解码和旧端消费。可以先交付前端路径，但“列表摘要待补”的缺口必须明确，不能继续宣称所有体验必需改动为零。

## 8. 实施顺序与验收门槛

1. **能力与依赖清点**：逐项登记现有菜单/操作/权限，固定归档基线，画出 App/Store/宿主依赖；确认哪些共享组件不能归档。
2. **WeUI与新外壳**：验证样式隔离，完成一级导航、页面栈、手机返回和桌面双栏。新页面接同一 client，不产生第二个连接 owner。
3. **会话状态闭环**：独立草稿、阅读位置、可见时标已读；接列表摘要的最小协议投影；完成联系人式空间与多 Session 的核心路径，以及最近10轮加载和稳定阅读。
4. **能力保全与项目页面**：接原消息操作、Fork、转发、授权、导入、空间/全局工具和公共 Preview。发现保持诚实空态。
5. **单入口切换和归档**：只有核心路径及保全矩阵通过，才将旧外壳移入 deprecated 并切 App 导出；不留下产品切换开关。
6. **dev交付**：同槽受控提交、配对构建和真实浏览器验证，提供精确版本入口；正式封版或合主干前按既定策略补完整门禁。

实现过程中按受影响模块和真实旅程验证，不为每个小布局调整重复跑跨仓全量。以下是下一版验收要求，不是本次文档已通过的测试：

| 旅程 | 必须证明 |
| --- | --- |
| 同一Space有两个Session，另一个Space同名；继续/新建/历史/深链 | 精确身份不混淆，默认继续目标可见；新建显式；打开一个不清除另一会话的未读 |
| 千轮历史冷打开、上拉分页时收到新回复、断线重连 | 首屏有界，历史不重不漏；待授权完整；锚点稳定；报告冷读与主线程成本，不以最终可显示代替性能验收 |
| A会话写草稿 → B会话 → 文件 → 返回A → 刷新 | 草稿隔离、附件恢复状态明确、原阅读位置可恢复 |
| 历史阅读期间收到新内容；切到空间页继续收到内容 | 不抢滚动，不误标已读；待批准与未读提示互不覆盖 |
| 手机返回、浏览器返回、深链进入、关闭预览 | 返回同一来源；一级页状态保留；不停止任务或重复建Session |
| 长按、多选、Fork、转发 | 原范围、预算、只读限制和目标机器合同保持；分别覆盖原生/重建与跨机 |
| 等待授权时断线/daemon重启 | 原请求恢复；决定后状态真实；不依赖旧Agent进程或UI挂载 |
| 空间A终端/文件打开后去B、切机器 | 所有操作目标正确；PTY不随无关列表刷新重建，关闭实例可回收 |
| 普通空间和PM项目打开HTML、反馈、来源失效 | 公共能力同等可用；不擅自选择会话，不暴露通用RPC |
| 320/390/768/1280宽度、软键盘、明暗主题、键盘操作 | 名称可读、无横向溢出、按钮可达、焦点正确、正文不被输入区遮挡 |
| 新入口构建、旧入口检查、缓存上限 | 无deprecated导入/扫描/路由/发布资源；Cloud和桌面嵌入兼容；长期切换会话资源有界 |

### 已实现的交互

- 会话、空间、发现、工具四个一级页面；手机进入详情后收起底部导航，通过页面返回恢复来源。桌面保留列表与内容并排，取消可见的已打开标签条。
- 空间以平面联系人列表呈现；资料页显示真实 Parent/子空间关系、继续目标、新会话、历史、导入和本空间工具。不改现有空间归属或团队配置。
- 一个 Space 的多个 Session 独立显示；正文摘要和内容游标支持未读标记，受阻筛选与未读独立。归档与恢复复用现有 RPC。
- 草稿按机器和 Session/本地草稿 ID 保存；保存文本及附件缺失数量，不把附件二进制写入 localStorage。未确认发送在刷新后提示检查历史，不自动重发。迟到的创建响应不抢回当前页面。
- 保留原消息选择、复制、转发、Fork、导入、授权、只读 Worker、公共 HTML Preview 和反馈入口。手机长按进入原消息选择模型。
- 空间文件/Git/终端仍从空间资料进入；全局工具在工具页面。发现显示空态，自动想法生成尚未新增。项目自定义页面继续是普通文件，不增加 PM 专属 UI 服务。
- 选择性引入 WeUI 2.6.26 的 Cell/Tabbar 样式，保留许可证并限定 `.genehub-ui` 作用域。

### 实际协议微调

| 位置 | 新增可选字段 | 行为与兼容 |
| --- | --- | --- |
| `subscribe` | `recentRounds` | Workbench 请求10轮；未传字段的旧客户端保持原快照行为 |
| `session.get` | `recentRounds`, `beforeItemId` | 同一读取权限下按稳定叙述 ID 加载更早窗口；不新增RPC |
| `SessionSnapshot` | `historyBefore`, `historyWindowed`, `historyExcerptIds` | 当前运行状态/待授权不被裁剪；超长正文按需通过既有 `session.narrative` 加载；历史与实时事件按ID合并 |
| `SessionSummary` / 已有 Session meta | `messagePreview` | 160字符可见正文、时间和内容ID；在用户输入与持久回复时更新，rename/心跳不增加未读；旧记录允许缺省 |

窗口优先按业务 round 取最近10轮，并设128叙述项的兼容上限；超过16KiB的用户/助手正文投影为摘要。此限制不改变 Agent 上下文或 Fork 数据。没有修改 Human 授权生命周期、Flow运行模型、Relay传输或文件权限。

### 验证与边界

13轮和1003轮真实 daemon 专项验证首窗、历史游标、并发新增输入、原文读取、旧客户端完整读取和重启后冷打开。1003轮测试中首窗11218字节，热读取3ms、重启后冷读取66ms；这些是该隔离环境的RPC耗时，不是移动设备首屏性能承诺。手动往前加载可以遍历1003个原始请求，ID无重复。

浏览器覆盖平面空间、作用域工具、公共预览、Fork/选择入口、独立草稿、刷新和手机返回；正式交付以同槽新构建的 smoke 与工作流记录为准。兼容测试按受影响范围选择，不为UI迭代重新运行跨仓全量。

仍沿用既有冷加载/克隆路径，不能称为O(1)磁盘读取；首屏窗口减少传输与初始DOM成本。订阅缓存和后台终端有界，但手动连续加载全部历史尚未虚拟化回收DOM。原阅读锚点位于尚未加载的旧页时明确提示继续加载，不悄悄声称已恢复。跨设备草稿/已读、自动发现、HTML调度桥、WorkflowManager团队迁移不在本版实施范围。
