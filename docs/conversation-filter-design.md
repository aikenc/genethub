# 会话筛选设计提案

2026-09-06。前三项修复上线后，基于 Open `6df3fc9` / Cloud `945e144` 核对。下文是第 4 项的后续提案，尚未实施；不把设想写成已有协议。

## 先把“会话太多”分成不同问题

本轮 dev 现场最初有 77 条未归档会话。现有主列表已隐藏受管 Worker 和已登记的子 Agent 会话；大量可见 PM 会话来自以前的开发 smoke。经目录和创建方式核对，归档了 24 条旧测试会话，以及同步脚本前本轮留下的 2 条。真实用户的 PM 对话保留。新 smoke 立即归档自己创建的 Session，并在重连后核对持久状态。

这不应变成产品按名称识别“测试”的规则。`PM`、`task_`、`smoke` 都不能作为通用隐藏条件；开发工具负责收尾，产品负责表达真实归属。

目前“主要 / 子 Agent / 全部”把两个不同维度压在了一个选项里：

- Agent 归属：一个 Session 属于一个 Agent，一个 Agent 有多个 Session；Agent 可以有 Parent。
- 受管来源：Workflow 创建的 Worker Session 带 `managed`，包含 Run、节点和父会话关联。

二者不等价。子 Agent 可以有用户直接发起的对话；受管 Session 也不能只靠目录深度识别。本次现场 Executor 的 Session 没有 `managed`，是依靠所属 Agent 的 Parent 被主列表排除的。

Fork 的 `lineage` 是历史来源关系，不能据此把新会话归为“子 Agent 会话”。Fork 后是否显示仍取决于新会话的真实归属和受管信息。PM 本身的普通用户会话应保留。

## 交互：固定头部、一个统一筛选入口

手机列表结构建议：

```text
会话                                      ＋
搜索 Agent 或会话
[Agent：主 Agent ▾]                  [筛选 · 2]
[全部状态]  [未读]  [受阻 ●]
[项目 A ×] [包含下级 ×]               ← 有条件才显示
───────────────────────────────────────
会话列表                                  独立滚动
───────────────────────────────────────
会话           Agent          发现          工具
```

示意中的项目 A、包含下级仅示范已选条件，不与默认“主 Agent”同时生效。实际选中后 Agent 按钮更新为所选名称或数量。

- Agent 入口复用有头像、搜索和单列密度的选择组件，支持多选；搜索范围包含所有可访问层级，不必先展开树才能找子 Agent。
- “全部状态 / 未读 / 受阻”是快捷条件。切换只改变状态和已读条件，保留 Agent、归档等范围；因此用“全部状态”，避免误解为整台机器的全部会话。
- “筛选”集中承载其余条件。手机打开一个可返回的筛选页，桌面用同一内容的侧面板。条件先编辑，点“应用”后统一生效；取消不改变原列表。
- 已应用条件显示可移除标签。标签很多时只保留一行和“还有 N 项”；不能再次把列表挤出屏幕。筛选页底部固定“重置 / 应用”，内容独立滚动。
- “重置全部”明确恢复默认主会话视图并清空搜索。单独关闭某个标签只移除该条件。
- 不新增底部 Tab，不把筛选页做成全局工具，不改变当前打开的 Session。

## 条件模型：同维度并集，跨维度交集

| 维度 | 建议选项 | 默认与含义 |
|---|---|---|
| 设备 | 当前已连接设备 | 外层上下文，按设备隔离条件与缓存 |
| Agent 范围 | 主 Agent、全部 Agent、指定 Agent（可多选） | 默认主 Agent，即没有 Parent 的已知 Agent |
| 下级范围 | 包含所选 Agent 的下级 | 指定 Agent 时默认关闭；去重并防止 Parent 环导致遍历循环 |
| 受管会话 | 包含受管执行会话；高级选项可只看受管 | 默认不包含；判据是 `managed`，不猜标题 |
| 状态 | 运行中、等待回应、失败、空闲、只读、已关闭 | 默认不限制；“受阻”是 waiting 或 failed 的快捷组合 |
| 已读 | 不限、未读 | 首版只表示此浏览器尚未读过的新内容 |
| 归档 | 未归档、已归档、不限 | 默认未归档；这是独立维度 |
| 搜索 | Agent 名称、会话标题 | 首版不承诺全文搜索 |

“主会话”作为默认预设，等于主 Agent + 不含受管 + 未归档 + 不限制状态。“整台设备全部会话”是显式预设，等于所有 Agent + 包含受管 + 归档不限；不能让一个名为“全部”的按钮只取消部分隐藏条件。

指定 Agent 就按 ID 匹配自己的会话，是否包含下级由可见开关决定。单纯选 Agent 不偷偷改变其他条件。若某个 Worker 只有受管会话，空结果要解释“有 N 条受管会话被当前条件隐藏”，并给出“包含受管会话”操作。从 Agent 资料页的“查看全部会话”进入，则明确带入该 Agent + 包含受管的预设，标签同步显示。

选多个 Agent 时属于任一所选范围即可；多状态也是任一匹配；Agent、状态、归档、已读和搜索之间同时满足。选择父和子且包含下级时，Session ID 去重，不出现重复行。

建议前端状态形状（不是新 RPC）：

```ts
type ConversationQuery = {
  agentScope:
    | { kind: "roots" }
    | { kind: "all" }
    | { kind: "selected"; workspaceIds: string[]; includeDescendants: boolean };
  managed: "exclude" | "include" | "only";
  statuses: SessionStatus[]; // 空数组表示不限
  unreadOnly: boolean;
  archive: "active" | "archived" | "all";
  search: string;
};
```

## 计数、受阻提醒和空结果

- 快捷标签数字是匹配当前 Agent、归档、受管和搜索范围的**会话数**，不是未读消息数或授权请求数。计算某个状态选项数字时，忽略当前状态/未读快捷条件，避免互相筛成零。
- 内部会话默认隐藏，但不能把需要处理的团队异常也藏掉：筛选入口可以显示“协作受阻 N”，点击明确切换到这些受管或下级会话的受阻视图，条件标签同步更新。无需读取全部 Session 的授权详情。
- `waiting` 只能表明会话处于等待状态。打开后才能读取具体请求；不能在列表里虚构“等待你的第 N 个批准”，也不能把 `idle` 解释为任务已成功。
- 无结果时显示当前条件、清除入口；区分无会话、被条件排除、目录尚未加载、查询失败。不要在加载或断线时显示确定的 0。
- Agent 目录缺失时不把归属不明会话自动归为主会话；“全部 Agent”仍可找到，并显示归属暂不可用。刷新成功后重新计算。
- 不支持恢复的历史仍可列出并解释；不能为了清爽把 `unsupported` 当作内部会话过滤掉。

## 列表、导航与消息阅读分开

所有入口复用 `ConversationList` 的查询模型和 `RecentSessions` 行组件。Agent 资料页、全局列表、从 Run 跳转都可以传入明确预设；不各写一套过滤函数。`AgentScopePicker` 复用 `AgentList` 行展示，但选择状态由统一查询拥有。

切换筛选不创建会话、不发送消息，也不标记已读。打开会话沿用现有消息流与最近轮次读取，返回时恢复该查询的阅读位置。状态轮询不能强制把列表拉回顶部；若最新消息改变排序，按可见 Session ID 保持锚点，用户在顶部时才直接呈现最新位置。

排序沿用最新持久消息的 `messagePreview.atMs`，缺失时回退现有时间字段，并用 Session ID 打破同时间的平局。筛选与刷新不应重建整棵列表 DOM。长列表再按实际性能决定虚拟化；虚拟化保留行高估计、头像尺寸和键盘焦点。

同设备切换底部 Tab 保留已应用条件。跨设备重新使用目标设备自己的条件；异步返回带连接身份校验，旧设备请求不能覆盖新设备结果。从 Agent 或 Run 定向进入会话，不偷偷改写用户全局列表的历史条件。

## 与现有协议逐项对齐

| 能力 | 已有来源 | 本提案首版 |
|---|---|---|
| 用户看到的 Agent | `workspace.list`、`WorkspaceInfo.id`、`agentSpace.parentWorkspaceId` | 前端按 ID 建索引与后代集合 |
| Session 归属 | `SessionSummary.workspaceId` | 用于 Agent 筛选；不是 `agentId` |
| 执行引擎 | `SessionSummary.agentId` | Codex / Cursor 等，若未来筛选另列“执行引擎” |
| 受管来源 | `SessionSummary.managed` | 保留一次性 Run/节点归属，显示不改变只读权限 |
| 状态、归档、标题 | `SessionSummary.status/archived/title` | 直接筛选，不新增状态机 |
| 未读 | `messagePreview.itemId` + `localConversation` 阅读标记 | 浏览器本地语义，不承诺跨设备同步 |
| 会话查询 | `session.list {workspaceId?, includeArchived}` | 复用现有查询；多 Agent 可在已加载摘要上筛选 |
| 历史读取 | `session.get` 的 `recentRounds` 和独立历史分页 | 沿用；不能把消息分页误认为 Session 列表已支持分页 |

`session.list` 当前没有通用过滤对象或游标。首版在当前设备的已授权摘要上统一派生结果，构建 Workspace Map 与后代集合一次复用，不逐行扫描目录。选择“已归档/不限”时请求 `includeArchived:true` 后本地精确过滤；“未归档”用 false。取消请求或按请求序号接收结果，避免快速切换归档时旧响应覆盖新条件。

不要为筛选先 `session.get` 每条会话，也不要订阅所有会话信息流。查询状态属于列表上下文，不能继续用一个全局 `includeArchived` 开关隐式改变 Agent 面板和其他入口的候选集合；共享数据缓存需要记录覆盖范围，视图各自拥有条件。

现有 `managed` 不能完整表示所有 Executor 或其他自动化来源。首版如实标为“受管会话”，不宣称已提供通用“所有内部会话”协议。需要在缺失 Parent 时仍精确识别机械 Executor，再单独评估向摘要增加可选 `origin` 投影：由已有持久执行事实生成，旧记录未知，不按名字回填，不新建 Session 类型。这不是本次首版依赖。

未来若完整摘要拉取已成为实测瓶颈，可增量增加查询/分页合同：条件签名、稳定游标、摘要计数与旧端回退一起设计。不能在前端只拿最近十条 Session 后过滤并声称“没有其他结果”。首版不增加待办中心、消息库或 daemon 筛选状态机。

## 落地顺序与验收

1. 先统一查询状态和派生函数，接入可搜索、多选的 Agent 范围；让主列表与 Agent 资料页共享行组件但独立查询状态。
2. 再把快捷条件、统一筛选页、条件标签、计数和空结果接到同一模型；移除原有语义重叠的范围下拉与归档全局开关。
3. 验证刷新与切换条件的并发、滚动锚点和设备隔离后，再考虑保存命名视图或协议性能微调。

验收以真实多 Agent / 多 Session 数据为准：

- 两个同名 Agent 通过 ID 正确区分；一个 Agent 下多个 Session 不合并。
- 根 Agent、子 Agent、受管 Worker、无 managed 的 Executor、用户 Fork 分别覆盖；默认主列表、指定 Agent、全部范围结果可解释。
- 受阻 + 指定 Agent + 归档 + 搜索组合，计数、列表和条件标签一致；切换快捷项不会清空 Agent。
- 直接从 Run 打开隐藏会话仍可达，受管只读权限不受筛选影响；返回后恢复全局列表条件和锚点。
- 断线、空目录、失效 Parent、快速切设备和归档请求逆序，不把旧数据或未知结果当作当前事实。
- 320px 手机、短视口和桌面的大量会话列表，导航与筛选动作始终可达。
- 搜索、筛选和预设切换只使用摘要；没有每个 Session 一次详情请求的放大。
