# GeneHub 产品与用户旅程

> 目标：**对用户最简单**。能跳过的登录就跳过；能用链接/扫码接力的就不要重新配置。  
> 原则：一个品牌（GeneHub）、一套 Web UI、多种壳（桌面 / 手机 / 浏览器）。  
> 安全侧的硬规则见 [security-model.md](./security-model.md)；下面的旅程已按其修订。

---

## 1. 用户只需要记住什么

1. 打开 **官网** 下载 PC App
2. 打开 App → **先体验**（可跳过登录）或浏览器登录
3. 之后用 **链接 / 二维码** 在手机、其他电脑、浏览器之间接力

不需要理解 relay、daemon、pairing offer、serverId。

---

## 2. 端到端旅程

### 2.1 PC 首次接入（主路径）

```
官网下载 GeneHub Desktop 安装包
        │
        ▼
安装程序（开始菜单 / Applications）→ 打开 App
        │
        ▼
托盘常驻 + 内置 daemon 后台运行（内置 agent 按需拉起）
（关闭主窗口 ≠ 退出；托盘可「打开主界面」唤醒）
        │
        ├─【推荐】点「登录并绑定这台电脑」
        │        → 浏览器打开确认页，显示一串配对码
        │        → 用户确认「把这台电脑加入我的账号」
        │        （底层是标准的设备码授权流程）
        │
        └─【更快】点「先体验」→ 临时用户，本机立即可用
                 → 同时生成恢复密钥，提示可导出
        │
        ▼
这台 PC 出现在「我的机器」；关窗后照样在线
后续：引导绑定邮箱 / GitHub
```

**成功标准：** 安装完成后，跳过登录 ≤ 2 次点击进入可用，并且**能真的跑起一条任务**（靠内置 PI Agent 保证，不依赖用户先装 Claude Code / Codex）。

桌面行为细则见 [desktop-client.md](./desktop-client.md)。

### 2.2 换设备：一次性链接

```
已登录用户（含临时用户）在 Web / Desktop 内：
  → 「在其他设备上打开」→ 生成一次性短链 + 二维码（15 分钟内有效）
        │
        ▼
另一台电脑的浏览器打开
        │
        ▼
建立**这台设备自己的**登录态（不是共享账号密码）
原设备上立刻能看到「已被某 IP / 某浏览器使用」，可一键撤销
        │
        ▼
看到同一套「我的机器」，一点即连
```

关键改动（原因见 [security-model.md](./security-model.md) §3）：

- 链接授予的是**设备会话**，一次性、短时效、可撤销，不是账号本身
- 「信任此设备」才升级为长期会话
- 公开机器、发起租用、绑定账号、删除机器这类操作，要求在**已信任设备**上确认

### 2.3 手机：扫码 + 原设备确认

```
手机装 GeneHub App（Capacitor 壳）
  → 手机上显示二维码
  → 用已登录的电脑/手机扫它
  → 在已登录设备上确认「允许 <设备名 / IP> 登录」
  → 手机进入同一账号（含临时用户）
```

不做"扫一下就进"——那等于二维码截图发出去就能登录。多一次确认，换来的是丢手机时能单独踢掉。

### 2.4 日常遥控

```
打开任意端（Web / Desktop / Mobile）
  → 已登录则直达机器列表
  → 点一台机器 → 进入工作台
  → （可选）把机器公开给团队租用
```

首次从新设备连某台机器时，界面会显示该机器的**公钥指纹**供核对；之后指纹变化会告警。

## 3. 身份模型（为「先玩后注册」设计）

| 身份 | 如何获得 | 能力 |
|------|----------|------|
| **临时用户** | 桌面端「先体验」 | 绑定并使用自己的机器、换设备接力；**不能**公开机器或租用他人机器 |
| **正式用户** | 邮箱验证 / GitHub OAuth | 全部能力；换设备不丢；团队角色 |
| **设备会话** | 桌面端首启、一次性链接、扫码 | 某个浏览器/App 上的登录态，可单独撤销 |

升级路径（非阻断）：

```
临时用户 ──绑定邮箱/GitHub──► 正式用户
         （机器归属、设备会话、审计记录一并迁移）
```

引导时机：第二次打开、第一次换设备、第一次想公开机器时。

**恢复路径（必须有）：** 临时身份存在本地，清缓存就没了，而机器已经绑在这个身份下。所以桌面端在创建临时用户时生成恢复密钥，并在托盘常驻「重新生成认领链接」——只要桌面端还在，机器就永远能被重新接管。

## 4. 信息架构（所有端同一套 Web）

```
GeneHub Web App（唯一 UI 源）
├── 登录 / 先体验落地页
├── 我的机器（在线状态、一键连接、在其他设备打开、设为公开）
├── 团队租用池（公开机器）
├── 工作台（自研，能力范围见 web-workbench.md）
└── 设置（账号绑定、设备管理与撤销、公钥指纹、安全日志）
```

壳只做三件事：

1. 打开上述 Web（或本地打包的同一构建）
2. Desktop：托管并守护内置 daemon（agent 由 daemon 自己按需拉起）
3. 系统能力：扫码、深链、开机自启

## 5. 「最简单」检查清单

| 场景 | 用户步骤上限 | 反模式（避免） |
|------|--------------|----------------|
| PC 新装先玩 | 下载 → 打开 → 先体验 | 先填服务器地址、先注册、先装 agent CLI |
| 绑定账号 | 点登录 → 浏览器确认配对码 | 手动复制 token、手动配 relay |
| 换浏览器继续 | 打开一次性链接 | 再装软件、再扫一次 PC 码 |
| 手机接手 | 手机出码 → 已登录设备确认 | 手机上再配 relay |
| 团队租一台公共机 | 登录 → 点租用 → 进入 | 找机主要二维码截图 |
| 升级正式账号 | 点绑定 → GitHub/邮箱 | 清数据重装 |

## 6. 用户动作对应的底层动作（用户不可见）

| 用户动作 | 底层实际 |
|----------|----------|
| 安装 Desktop | 写入默认 Hub 地址；启动 daemon |
| 先体验 | Hub 建临时 user + 设备会话 + 恢复密钥 |
| 登录并绑定这台电脑 | 设备码授权 → 机器登记 → `machines` 行 active |
| 点「连接」自己的机器 | Hub 校验归属后下发连接凭证 → 客户端按「本机 → 局域网 → 转发」顺序接入（端到端加密） |
| 点「连接」租来的机器 | 不发 offer；操作经 Hub 执行通道转发（可撤销、可审计，平台可见） |
| 在其他设备打开 | Hub 签发一次性设备会话链接 |
| 公开 / 租用 | Hub 改 visibility + 建租约，并校验隔离约束 |

**裸 pairing offer 不进入任何分享给人类的链接。** 详见 [security-model.md](./security-model.md) §4。

## 9. 已拍板的决策

| 议题 | 结论 |
|------|------|
| 分享语义 | 授予设备会话，不共享账号；敏感操作需已信任设备确认 |
| 工作台 UI | 自研，复刻主流工作台约 60% 能力（[web-workbench.md](./web-workbench.md)） |
| 默认 agent | 内置 Genet Agent，保证零配置可跑；用户已装的其他 agent 平级可选 |
| 临时用户公开机器 | 不允许，引导升级正式账号 |
| 租用通道 | 走 Hub 执行通道，不下发 offer |
| 链接时长 | 一次性 + 15 分钟；「信任此设备」另算 |
