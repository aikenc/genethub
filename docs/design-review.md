## 第一轮（2026-07-28 白天）

对第一版文档与当时的过渡部署做了一次核对。

**一句话总结：** 最大的问题是**在自己服务器上跑了一个能执行代码的守护进程，只为托管几个静态文件**。

### P0 — 已修复的线上风险

| # | 问题 | 处置 |
|---|------|------|
| 1 | 过渡站点背后跑着一个以普通登录用户身份运行、模型凭证可用、且连着公网中转的守护进程；它的配对凭证曾被明文打印。密码只保护直连路径，中转通道不校验密码，因此持有该凭证即可在服务器上执行代码 | 停掉进程；删除身份文件与密钥对完成轮换；站点改为 Caddy 直接托管静态产物 |
| 2 | 用一个功能完整的执行型服务充当静态文件服务器 | 改为 `file_server`；`/api/*`、`/ws` 一律返回 404 |

教训：**能执行代码的东西不要顺手拿来做别的事**。省下的十分钟配置，换来的是一个完整的远程执行入口。

### P1 — 设计前提错误

| # | 问题 | 决策 |
|---|------|------|
| 3 | 连接凭证被当成"租期结束可轮换"。实际上机器身份与密钥对是持久化的，重启不变；作废必须删文件，且会让机主自己的所有客户端一并失效；握手也不校验客户端公钥 | 承认这类凭证**不能按人撤销**；只发给机主本人的设备，租用改走可撤销的执行通道 |
| 4 | 租用的隔离粒度为零：租客拿到整机能力，还会用掉机主的模型凭证与额度 | 公开机器必须先满足工作目录白名单、自带 API Key、用量上限、单活跃租约、随时收回；MVP 阶段租用只对内部可信成员开放 |

### P2 — 用户旅程

| # | 问题 | 决策 |
|---|------|------|
| 5 | "分享链接 = 登录态"实为账号接管链接，转发出去等于交出机器 | 链接改为授予**设备会话**：一次性、≤15 分钟、原设备可见可撤销；敏感操作要求已信任设备二次确认 |
| 6 | 临时用户无恢复路径，清缓存即失去对已绑机器的控制，机器变孤儿 | 桌面端生成恢复密钥（服务端只存哈希）；托盘常驻「重新生成认领链接」 |
| 7 | 引入服务端目录后仍沿用"平台看不到内容"的表述，但分发公钥本身就具备中间人能力 | 客户端显示公钥指纹并在变化时告警；对外表述按通道分别说明，见 [security-model.md](./security-model.md) §1.1 |
| 8 | 「下载即玩」缺一环：新机器没装任何 coding agent 就跑不了任务，MVP 验收标准不成立 | 桌面端内置一个默认 agent |

### P3 — 运维与一致性

| # | 问题 | 决策 |
|---|------|------|
| 9 | 站点进程靠 `nohup` 起，重启即失；无日志轮转与备份 | 常驻服务一律用 systemd 或容器 `unless-stopped` |
| 10 | 域名与命名不一致，产品名与入口名对不上 | 目标形态：`genethub.com`（官网）/ `app.genethub.com`（工作台 + Hub）；过渡域名用完即下线 |
| 11 | 观测审计排在 M4，但 MVP 就已把服务暴露在公网 | 审计表与关键事件打点提前到 MVP，查询 UI 仍可放后面 |

## 第二轮（2026-07-28 晚）

两条新需求进来：**必须同时支持多种 coding agent**，以及**前端要复刻主流工作台约 60% 的能力**。它们推翻了第一轮的几个前提。

### 被推翻的结论

| 原结论 | 新结论 | 为什么变 |
|--------|--------|----------|
| 集成第三方守护进程，Hub 去实现它定义的协议 | **自研 Rust 精简 daemon 与自有协议** | 要接多种 agent、要自有归一化事件模型，本来就得重写；顺带拿回协议主导权 |
| 内置一个复用 Node 运行时的默认 agent | 自研 Rust 内置 agent，**且只是众多 adapter 之一** | 用户真正想用的是自己已付费的 agent；内置的只负责"第一分钟能跑" |
| 靠依赖裁剪 + 单文件打包压到 150MB | 两个进程都是 Rust 静态二进制，预算降到 60MB 量级 | 运行时与依赖树整块消失，原先最大的不确定项不存在了 |
| 先 fork 一个成熟工作台再魔改 | **自研前端** | fork 纪律的前提是"不碰会话与协议层"；协议自研后这条守不住 |
| 接受 AGPL 义务，准备源码发布通道 | 不再产生衍生作品 | daemon、前端、agent 全部自有实现 |
| 中转服务补邀请码准入 | **删除该项** | 转发折进 Hub 后身份即准入 |

### 新增的架构约束

1. **agent 是插件，内核不认识任何具体 agent**——内核里不允许出现按 agent 名字的分支。
2. **客户端协议是产品资产**——不让任何 agent 的线格式外泄成对外协议。这是本轮最容易犯、代价最大的错误。
3. **MVP 必须跑通多种形状的 agent**——只接一种时写出的"抽象"必然是那一种的形状。
4. **转发层与控制面合并部署但分模块**——单向依赖 + 可远程化接口 + CI 检查依赖方向，否则"以后能拆"是空话。
5. **不设单元测试层**——AI 写的代码与测试同源同假设，测试会陪着错误一起变绿。判据改为"有没有独立于实现的事实来源"，见 [testing.md](./testing.md) §1.1。

完整论证见 [architecture.md](./architecture.md)。
