# GeneHub 工作台（前端）

> 自研，不 fork。目标是复刻成熟工作台**最重要的约 60% 能力**。  
> 决策依据见 [architecture.md](./architecture.md) §6；前端只认 [architecture.md](./architecture.md) §4 的归一化协议。

---

## 1. 「60%」怎么定义

不是砍掉 40% 的代码量，而是**保住 100% 的主路径，砍掉长尾**。主路径是这一条：

```
连上机器 → 选 agent 和模型 → 发任务 → 看流式输出和工具调用
      → 审批 → 看 diff / 改文件 → 跑终端 → 提交 → 换设备接着看
```

判据：**这条路径上任何一环缺失都不算 MVP；不在这条路径上的一律进 §4 的不做清单。**

对照能力盘点，主流工作台约 16 个功能域、上百个特性；本文纳入其中 9 个域的核心项，特性数量约 60%，但覆盖了日常 90% 的操作频次。

## 2. 做什么（MVP 范围）

### 2.1 会话工作台（最高优先级）

| 能力 | 说明 |
|------|------|
| 流式对话 | 增量打字机效果、markdown 渲染、代码高亮 |
| 推理块 | `Reasoning` 折叠展示，默认收起 |
| 工具调用渲染 | 按 `ToolCallDetail` 分派渲染器：**shell / read / edit / write / search** 五种专用 + `unknown` 兜底 |
| Diff 视图 | `edit` 的行级 diff 着色，支持展开全文 |
| 输入区 | 多行输入、发送/停止、图片与文件附件、排队消息 |
| 审批卡片 | 权限请求内联在时间线底部，单选/多选/文本回答 |
| 自动滚底锚定 | 新内容时保持视口贴底，用户上滚则解除 |
| 中止 | 停止按钮真能打断当前 turn |

### 2.2 Agent 与模型控制

agent 选择器、模型选择器、思考档位、权限模式。**按 `Capabilities` 渲染**：agent 不支持切模型就不显示这个控件，而不是点了报错。

### 2.3 工作区与导航

左侧栏（项目 → 工作区列表 → 会话）、标签页、新建会话、归档、会话重命名。标签页类型 MVP 只做四种：**会话 / 文件 / 终端 / 变更**。

### 2.4 文件与 Git

| 能力 | 范围 |
|------|------|
| 文件树 | 浏览、打开、基础右键菜单 |
| 文件查看 | 语法高亮预览 + 可编辑保存；图片预览 |
| 变更面板 | 未提交改动列表 + 逐文件 diff（unified 优先，split 后做） |
| Git 操作 | status / commit / pull / push / 分支切换 |

### 2.5 终端

xterm.js 终端标签页，多开、可调整大小、输出滚动。

### 2.6 多机与配对

机器列表与在线状态、切换机器、扫码/链接配对、公钥指纹展示。

### 2.7 设置

只做四页：**通用 / 外观（主题与字号）/ 模型凭证 / 机器与连接**。

### 2.8 响应式

一套代码覆盖宽屏与窄屏：窄屏下侧栏抽屉化、工具详情走底部抽屉、输入区吸底。手机浏览器与 Capacitor 壳共用这一套，不做第二份 UI。

### 2.9 基础体验

命令面板（⌘K：跳转会话/工作区/切模型）、一组核心快捷键、任务完成与审批的桌面通知。

## 5. 技术选型

| 层 | 选择 | 理由 |
|----|------|------|
| 框架 | React + TypeScript + Vite | 生态与招人面最宽；Tauri / Capacitor 直接装同一份产物 |
| 样式 | Tailwind + CSS 变量主题 | 主题切换靠变量，不靠重新编译 |
| 服务端状态 | TanStack Query | 文件树、git、catalog 这类请求-缓存场景 |
| 客户端状态 | Zustand | 面板布局、草稿、会话时间线 |
| 终端 | xterm.js | 事实标准 |
| 编辑器 | CodeMirror 6 | 比 Monaco 轻很多，够用 |
| 高亮 | Shiki（预编译主题） | 与编辑器主题一致 |
| 图标 | Lucide | |

**不选 React Native / Expo**：跨平台价值主要在原生 App，而我们的桌面是 Tauri WebView、手机是 Capacitor WebView，两者都吃 Web 产物；引 RN 只会平白多一层抽象和构建复杂度。

## 6. 状态与数据流

```
WebSocket（自有会话协议）
    │
    ├─ SessionEvent ──► timeline store（Zustand）──► 会话视图
    ├─ 推送快照     ──► TanStack Query 缓存失效  ──► 文件树 / git / 机器列表
    └─ PTY 输出     ──► 直接喂给 xterm，不进 store
```

三条规则：

1. **时间线不进 Query**：它是流，不是可缓存的请求结果。
2. **PTY 输出不进 store**：高频二进制流进状态管理只会拖垮渲染。
3. **每台机器一个连接与一份 store**，切换机器不互相污染。

## 7. 与桌面 / 手机壳的关系

同一份构建产物三处复用：浏览器直出、Tauri 打进桌面包、Capacitor 打进手机包。

这一点值得说明白，因为它常被误解：**PC 端"不依赖 Node"并不意味着 PC 端不能用 H5**。Tauri 的窗口内容就是本项目这套前端，只是渲染它的是系统 WebView 而非 Chromium，驱动它的是 Rust 而非 Node。被排除的是 Node 运行时进程，技术栈本身没有任何降级（见 [desktop-client.md](./desktop-client.md) §4.1）。

宿主差异收敛在 `src/host/` 一个模块里，对外暴露统一接口：

```ts
interface Host {
  connect(machine: MachineRef): Promise<Channel>; // 桌面直连 127.0.0.1，浏览器走 Hub 转发
  notify(n: Notification): void;
  openExternal(url: string): void;
  pickDirectory?(): Promise<string | null>;       // 可选能力，缺失即不渲染入口
}
```

**业务组件不允许出现 `if (isTauri)`。** 需要区分宿主时，要么走上面的接口，要么把该能力声明为可选并在缺失时隐藏入口——和处理 agent `Capabilities` 的做法一致（§2.2）。否则宿主分支会长满全项目，最后变成事实上的两套前端。

壳自身只提供三件事：**深链、通知、扫码**。任何"只有桌面能用"的功能都要先问一句能不能用 Web 能力实现。
