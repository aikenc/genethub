# 工作台（前端）

> 自研，不 fork。目标是复刻成熟工作台**最重要的约 60% 能力**。  
> 决策依据见 [architecture.md](./architecture.md) §7；前端只认 [architecture.md](./architecture.md) §4 的归一化协议。

---

## 1. 「60%」怎么定义

不是砍掉 40% 的代码量，而是**保住 100% 的主路径，砍掉长尾**。主路径是这一条：

```
连上机器 → 选 agent 和模型 → 发任务 → 看流式输出和工具调用
      → 审批 → 看 diff / 改文件 → 跑终端 → 提交 → 换设备接着看
```

判据：**这条路径上任何一环缺失都不算 MVP；不在这条路径上的一律进 §4 的不做清单。**

对照能力盘点，主流工作台约 16 个功能域、上百个特性；本文纳入其中 9 个域的核心项，特性数量约 60%，但覆盖了日常 90% 的操作频次。

## 2. 做什么（MVP 范围）

### 2.1 会话工作台（最高优先级）

| 能力 | 说明 |
|------|------|
| 流式对话 | 增量打字机效果、markdown 渲染（GFM：列表/表格/删除线）、代码块带语言标签和复制按钮 |
| 推理块 | `Reasoning` 折叠展示，默认收起；daemon 只下发 Agent overview 或前 24 个 Unicode 字符 |
| 过程展开 | 正在跑的那一轮，它最后一个 trunk 和其中最后一个 batch 默认展开——看 Agent 干活是这一轮存在的理由，要点一下才能看见等于没有。tail 往前走时旧的自动收起，已结束的轮次全部收起；用户手动点过的那一块脱离这个默认，不会在下一次刷新时被合上 |
| 工具调用渲染 | session 只下发语义类型与裁剪后的 `overview / input / output`：标题最多 64 字符，input 一行最多 64，output 只留前二后二行且每行最多 64；列表用 Emoji 区分命令、读写、搜索、网络、计划、子 Agent、MCP 等类型，失败只加 `!`，展开只显示并可复制输出，不提供原始 payload |
| Turn 页脚 | 重点显示 GitHub 风格相对完成时间、耗时和输出 token；点击 token 才展开 cached input / input / output / tools，另提供复制回答和能力感知的真实 Fork |
| Diff 视图 | `edit` 的行级 diff 着色，支持展开全文 |
| 输入区 | 多行输入、发送/停止、图片与文件附件、排队消息 |
| 思考强度 | 独立于「模式」的一条轴：档位由当前模型自己报（Claude Code 每个模型报自己的 `low…max`），模型没有档位就不出现这个控件；不知道当前在哪一档时显示「默认」而不是假装是最低档 |
| 斜杠命令 | 输入 `/` 打开当前 agent 自己报的命令表（名字、参数提示、说明），上下键选、Enter/Tab 补全；执行就是普通文本，不需要额外协议 |
| 审批卡片 | 权限请求内联在时间线底部，单选/多选/文本回答 |
| 自动滚底锚定 | 新内容时保持视口贴底，用户上滚则解除 |
| 中止 | 停止按钮真能打断当前 turn |

### 2.2 Agent 与模型控制

agent 选择器、模型选择器、思考档位、权限模式。**按 `Capabilities` 渲染**：agent 不支持切模型就不显示这个控件，而不是点了报错。

这几个控件的值一律取自会话状态，不留一份本地副本——同一个会话在手机和电脑上同时开着时，两边看到的必须是同一档。代价是 daemon 必须把每次记下的选择都广播出去：**首个 prompt 之前 agent 进程还没起**，这也是最常见的选择时机，而这条广播一度缺失，于是选完立刻被下一次重绘弹回原值，看着就是「下拉选不动」。同理，agent 没报过的值要在 daemon 侧当场拒掉（进程没起时对着它的 catalog 校验），否则界面会围绕一个根本没生效的选择重绘。

原生下拉的弹层是浏览器引擎画的，取的是 `color-scheme`，不是我们的 class。主题里少这一行，弹层就用系统亮色皮肤配我们的浅灰文字（白底白字），并且会随系统或 WebView 改主意而跳色。**两套令牌都要各自写一行 `color-scheme`**，否则亮色主题只换了我们画的部分，引擎画的那部分还停在暗色。

### 2.3 工作区与导航

主壳是 IDE 式三栏，不是五个互斥的站点 Tab：

```
┌───────────────────────────────────────────────────────┐
│ GeneHub  文件 视图 帮助                    ─  □  ×    │ ← 自绘标题栏（仅桌面壳）
├──────────┬──────────────────────────┬──────────────┤
│ 左栏     │ 可关闭的标签行             │ 右侧面板     │
│ 新建会话 │ ──────────────────────── │ Changes /   │
│ 搜索     │ 当前标签内容（默认聊天）    │ Files       │
│ 项目→会话│ 底部浮动 Composer         │ 与聊天并排   │
│ 底栏入口 │                            │              │
└──────────┴──────────────────────────┴──────────────┘
```

- **左栏**：新建会话、跨项目搜索、**「项目 → 会话」两级树**；文件 / 终端 / 设置是底栏入口，点开后变成标签，不是把整页切走。
  - 项目行显示名字、运行中会话数、折叠箭头；空项目写一行「还没有会话」，不留一段看不懂的空白。点项目行把它设为当前项目，右侧的文件树、终端、变更都跟着走。
  - 项目名前以目录或 workspace 图标区分单目录与 `.code-workspace`。项目菜单的“从列表移除”是可恢复的登记操作：先在原地确认，文件和会话不删除；重新打开同一首根继续原历史。运行中或等待交互时禁用该动作。
  - 每个会话显示带文字语义的五态图标：已完成未阅读、已完成已阅读、运行中、等待交互、运行异常；不能再用灰/绿圆点让用户猜。未读按本机 `updatedAtMs` 与最后阅读时间判断，执行状态由 daemon 定期刷新。
  - 这棵树靠的是 `session.list` 的 `workspaceId` 可以省略——daemon 收到 `null` 就返回全部会话（`SessionManager::list`），一次请求画完整棵树，不需要每个项目一次往返。
  - **由此带来一条必须遵守的约束**：会话列表里现在有别的项目的会话，所以 `selectSession` 必须把 `activeWorkspaceId` 一起改过去，否则点开另一个项目的对话，右边的 diff 还是上一个仓库的——而且看不出来。
  - 折叠状态、当前视图记在 `localStorage`，和配对过的机器一样是「这个人怎么摆这一个窗口」，不上传 daemon：否则手机会把电脑上的排版改掉。
  - 「按状态分组」（Working / Ready）保留为第二视图。两个问题不一样：「我在做哪些项目」和「现在有什么在跑」，后者是横跨项目的，所以那个视图里每行要带上项目名。
  - 每一行右侧有一个 `⋯`，里面是**重命名**和**删除**。删除要在原地再问一次，而不是用 `confirm()`：系统弹窗是这里唯一一块没法配色、点旁边关不掉的界面，在手机上它还会以系统警告的样子盖到一个从不弹系统警告的 app 上。这个 `⋯` 在触屏上**常驻**——hover 是手机唯一做不出来的交互，把「删掉一个对话」的唯一入口藏在 hover 后面，等于它根本不存在。
- **标签**：每个会话、文件面板、终端、设置各自是可关闭标签；关掉不等于销毁左侧会话列表里的记录。
- **右侧面板**：Changes / Files 可与聊天并排打开——看 diff 时对话还在。
- **Composer**：贴在聊天底部的浮动输入区，模型与思考档以内嵌芯片形式放在输入框下方；发送是上箭头，运行中变成停止。

**打开项目的入口必须在界面上。** 这句话本不该需要写，但它确实缺过一段时间：协议层有 `workspace.open`、桌面壳有原生目录选择器，界面上却任何地方调不到它们，于是新装用户看到的是所有按钮都灰着、也不说为什么的工作台。

两种形态，区别不是装饰性的：桌面端 daemon 就在本机，提供原生“打开项目文件夹”和“打开工作区”选择器；浏览器连的是另一台机器，本地没有东西可浏览，于是通过 E2EE `directory.list` 浏览**那台机器上**的子目录和 `.code-workspace` 文件。Windows 盘符根的上一级进入机器根列表（`path: ""`），以便换盘；选夹 Dialog 可用 `directory.mkdir` 新建文件夹。打开入口优先从当前选中项目的首根开始；没有当前项目时，使用该浏览器为这台目标设备记住的最后目录，再失败才回到 daemon 的 home。记忆按设备指纹/配对身份隔离，不保存 Relay URL 或临时票据。目录/定义不存在或无效时自动尝试下一级安全回退，并把最终错误显示出来，而不是静悄悄什么都不发生。工具 → 文件面板在预览之外提供轻量整理：`file.mkdir` / `file.copy` / `file.move` / `file.delete`，始终锁定在已注册项目根内。

`.code-workspace` 采用 VS Code 的多根体验子集：Explorer 以 `folders[].name` 显示多个顶层目录，但显示名从不参与文件或 Preview 寻址。直接打开 folder 与打开 `.code-workspace` 是不同项目身份；每个真实目录由 daemon 级随机 `rootHandle` 统一映射，同一 canonical directory 跨项目复用。节点路径统一是 `<rootHandle>/<relative-path>`，所以改 label、重名或调整顺序不会改变历史链接。Agent、会话、终端和 Git 仍以第一个目录为工作区，不把现有 Agent 生命周期改造成多 cwd。

### 2.3.1 第一次打开

发第一条消息需要三样东西同时成立：一个项目、一个模型密钥、一个会话。旧的做法是三样都不满足时把控件一律置灰，原因藏在别处——用户看到的是一个坏掉的软件。

现在只有一样还需要问用户，就是密钥：

- **项目**：daemon 给从没用过的机器准备了一个默认工作目录（见 `daemon.md` §3），所以界面加载时手上一定已经有一个工作区。用户当然可以再打开自己的项目，但那是选择，不是门槛。
- **会话**：连上以后直接落到会话里——有历史会话就回到最近动过的那个，一个都没有就替他开一个空的。「回来继续上次那件事」几乎总是对的，而「新建会话」这个按钮里没有任何值得问一句的决定。
- **密钥**：这个必须问，因为界面没法替他去拿。此时才出现整页提示，并直接指向设置页。

判断「有没有密钥」用的是 agent 目录里有没有模型，不是去读设置：目录本来就是按已配置的 provider 拼出来的，它和「这一轮能不能真的跑起来」是同一个判断。没密钥时也不会替他建会话——建了也发不出去，反而把那句该说的话挤掉了。

#### 2.3.2 新会话是草稿，发出第一条消息才落到机器上

「新建会话」不发 `session.create`。它只是把界面切到一个空对话（store 里的 `draft`），真正的 `session.create` 发生在第一次 `send` 的那一刻。

这条以前是反过来的，代价是用户报上来的那句话：**「新会话即使没有内容也会残留在会话列表中」**。按一下就写一条到磁盘，于是每一次误触、每一次点进去看看又退出来，都在侧栏里留下一行叫「新会话」的东西——彼此之间没有任何可区分之处，而且当时连删除都没有。

由此有三条约束：

- **草稿要能装下选择**。在空对话里选模型、选模式、选思考档，此时还没有会话可以承载它们，所以记在 `draft` 上，`session.create` 时一起带过去（`effortId` 例外：create 没有这个字段，建完紧接着补一次 `session.setEffort`）。丢掉它们的后果是「在新对话里选了个模型，什么都没发生」。
- **只能有一个草稿标签**（`chat:draft`）。`selectSession` 无论因为什么被调用，都要顺手把它清掉——草稿变成真会话时是这样，用户中途去点别的会话时也是这样。否则会多出一条打开是空的「新会话」标签。
- **换 agent 也走这条路**。同一个会话不能移交给另一个 adapter（各家对「会话」的定义互不兼容），所以在 Composer 里换 agent 是开一个新的空对话，而不是新建一条会话记录。

**打开项目**这条路仍然要随时可达（左栏常驻），只是不再挡在第一条消息前面。

### 2.6 设备管理

**这一块在开源仓库里，不在别处。** 用户看自己有哪些机器、哪台在线、把设备配对进来、撤销、核对指纹——这些是"我的设备"，属于用户自己。

#### 2.6.0 目标切换器：本机只是其中一项

「我能控制哪些机器」不是一项设置，是这个应用的主导航。它长在侧栏顶端，任何时候都能看见**当前连着哪台**——底下那棵项目树全是那台机器上的本地路径，不标出来就会被读成一份跨机的总目录。

数据来自 `Host.targets()`：桌面壳给出本机加本地名册，浏览器给出本地名册。`Host` 上这一对方法是中性的，不含任何账号字段。

**配对了 Hub 的机器还多一份名单：账号名下的那些。** 桌面壳在列表里合并它，来源是 `hub.machines`——问的是自己脚下那个 daemon，由 daemon 拿上行凭证去问 Hub。切过去时 `hub.connect` 同样经由本机 daemon 铸票据，所以远端掉线后重拨仍然找得到人问（那正是远端不可达的时刻）。

这条路径是为了让这个应用**始终只装开源代码**：官方安装包与你自己编译出来的是同一份前端，账号那一侧全在服务器。自建 Hub 实现同样两个端点，这里就一样能用；没有 Hub 的机器答一个空列表，切换器只剩本地那些。

两台名单里的同一台电脑目前按**稳定设备标识摘要**去重：Hub 的 machine id 和本地配对 id 是两个命名空间。这个摘要不是已验证公钥，不能承担中间人检测；未来 canonical machine identity 落地后才改用被协议验证并 pin 的公钥。少了去重，本机会出现两行，其中一行还要绕中转回到脚下这台 daemon。

切换器底下有一项「我的账户…」。账户页是 Hub 的页面，在系统浏览器里打开，链接由 daemon 铸的一次性认领链接带住身份（`hub/account.ts`）——直接开 `/account` 的话，那个浏览器在 Hub 眼里是个陌生人，接着登录会绑出一个新账号。

两件事因此成立，都是有意的：

- **桌面端不等于只能看本机。** 本机是默认落点（延迟最低、断网也在），不是唯一项。
- **工作空间不加机器前缀，也不做跨机聚合。** `workspace.list` 只答当前那台 daemon，账号下压根没有一份跨机项目表可供前缀；加了只会假装有，切一次机器整棵树就换掉，前缀反而骗人。正确的导航是层级：先选机器，再看项目。

没实现 `targets()` 的 Host 就退化成今天的样子——一个 endpoint，没有切换器。

页面最上面一块是**「在手机上打开」**:一个按钮,出链接和二维码。它在最上面而不是在设置里,因为这不是一项设置,它是"我怎么在沙发上用这台电脑"的答案——人是带着这个问题打开这一页的。链接从哪来取决于这台机器怎么可达:经 Hub 时,链接把另一个浏览器登进同一个身份;自建 relay 时,链接把另一台设备直接和这台机器配对。没连 Hub 也没开远程访问时,这里指出**唯一**缺的那一步,而不是摆一个按下去没反应的按钮。

下面还是原来的两件事：

| 这台机器 | 我的机器 |
|---|---|
| 开不开远程访问（填 relay 地址与 join token） | 我配对过哪些机器，哪台在线 |
| 出示配对链接 + 二维码，把新设备加进来 | 连过去、改名、忘掉 |
| 已授权设备列表，逐个撤销 | 指纹核对 |

两侧数据来源不同，这个区别不是装饰性的：**左侧来自 daemon**（它才知道谁被授权了），**右侧来自浏览器本地**（"我配对过谁"是这个客户端自己的记忆）。所以换个浏览器右侧就是空的，界面要直说这一点，而不是让用户以为机器丢了。

二维码下面永远并排一个可复制的链接。扫码要 `getUserMedia`，而浏览器只在 HTTPS 下给权限——自建部署经常没有，手动打开链接必须是一等公民而不是降级方案。

配对 UI 完全由 daemon 返回的状态驱动，前端不自己记"现在到第几步了"——重开一个窗口、刷新一次页面，它的记忆就和机器上的真相分叉了。

账号体系的界面不在本仓。它经三个可选口子插进来，不传就是自建版今天的样子：

| 注入点 | 传了会怎样 | 不传 |
|---|---|---|
| `App` 的 `welcome` | 这个浏览器还没有机器时，由它决定显示什么 | 老实说一句"还没配对过机器" |
| `App` 的 `extraTabs` | 侧栏多出几页，各自去调各自的后端 | 没有这些页 |
| `Host` 的 `targets` / `openTarget` | 切换器里是账号名下的机器 | 本地名册：这个客户端配对过谁 |

工作台对账号是**零认知**：注入进来的组件自己知道要调谁，这里既没有"控制面"抽象，也没有"有没有账号"的开关。第三个口子尤其要守住这条——它交换的是「机器 id 和一个能连上去的 endpoint」，不是「用户是谁」。

### 2.7 设置

只做四块：**外观 / 模型凭证 / Agent 状态 / 远程访问**。

外观是暗色 / 亮色 / 跟随系统三态，存在 `localStorage`（`theme/store.ts`），**不进 `settings.*`**：daemon 的设置是那台机器的，所有连上来的客户端共用一份，而「暗房间里的手机」和「办公室灯下的笔记本」问的根本不是同一个问题，一个答案必然在其中一边是错的。

两套令牌都在 `theme.css` 里，形状一样、名字一样，所以没有任何组件需要知道当前是哪一套。亮色不是把暗色反过来：反过来会得到近白的侧栏贴着纯白的正文，所有分界线一起消失。这里的层次是反向的——页面最亮，越靠近读者的面越往下压一档。绿色主色两边同一支（那是品牌），但 `--ok` 和 `--accent-bright` 必须换，它们在暗色里是淡绿，放到白底上就看不见了，而这两个是当文字读的，不只是圆点。

`:root` 上放的是暗色，作为兜底：脚本没跑起来的页面应该是这个应用一直以来的样子，而不是一张画了一半的白页。首屏不闪的做法是在 `main.tsx` 里 React 渲染之前同步打 class——样式表是阻塞渲染的，这段代码在它之后、第一帧之前跑完。**没有用 `index.html` 内联脚本**：桌面端 CSP 只允许 `'self'` 的脚本，为了半帧去放开 inline 不划算。

密钥是**只写**的：存进去之后接口只回"配没配"，不回值。一个以后可能被攻破的客户端，不该有能力读出它从没见过的凭证。

模型凭证这一块，每行除了 Key 还说三件事:

- **地址**。自带地址的 provider 那一栏永远不是空的(空框会被读成"我们也不知道该发去哪"),而一把 Key 会被发到哪个地址,没有理由不告诉本人。
- **对方报上来的模型**。填完 Key 就在同一行显示"N 个模型可选:…",不用去聊天页找。列表是问 provider 要的,不是我们维护的表(见 [builtin-agent.md](./builtin-agent.md) §7.2)。
- **拿不到列表时,对方原话**。一把被拒的 Key,从外面看和"这软件坏了"一模一样:选择器空着,什么也没说。provider 已经说明了原因,那句话就放在输 Key 的地方。

还能**添加自定义 provider**:id、显示名、地址、Key、方言(OpenAI 兼容 / Anthropic 兼容),以及可选的手写模型列表(给不能列出自己模型的地址,比如裸 llama.cpp)。地址是必填项,而这就是这个表单最要紧的一条约束——一个有 Key 没地址的 provider 曾经继承了 OpenAI 的地址。自己加的能删,我们自带的三个不能(删了下次启动还在,那看着像 bug),只能清空它的 Key。

### 2.8 响应式与移动端

一套代码覆盖宽屏与窄屏，不做第二份 UI：

| 屏幕 | 布局 |
|------|------|
| 宽屏 | 左栏会话树常驻，可从「视图」菜单收起；主区可关标签 + 聊天；Changes/Files 可右侧并排 |
| 窄屏 | 会话树是盖在对话上的全高抽屉；右侧面板不存在；标签行只在不止一个标签时出现 |

抽屉和「收起左栏」是两件事，代码里也是两个状态：抽屉默认关着，因为它盖住对话；收起是宽屏上有人主动要回这块地方，默认不收，因为左栏就是这个工作台的读法。

窄屏上**只有三样常驻 chrome**：抽屉入口、当前对话的名字、新建。连接状态只在不正常时才出现一行字——一个每屏都在的绿勾是多一样要读过去的东西，而这条 bar 只放得下三样。Changes / Files 那两个按钮在窄屏上直接不渲染：它们开的是一个只存在于宽屏的右侧面板，在手机上按下去什么都不会发生。

#### 窄屏上不可以妥协的四条

前三条各自对应过一条用户报上来的原话，都不是理论问题。

1. **整页不能滚。** `body` 是 `position: fixed; inset: 0; overflow: hidden`，只有里面的面板能滚。光写 `overflow: hidden` 不够：iOS 在输入框获得焦点时会去**滚动页面**把它露出来，而 Composer 贴在底部，于是顶栏和标签行被顶出屏幕，键盘收起后也回不来。固定的 body 没有可以滚到的位置，问题就不存在了。
2. **表单控件的字号一律 ≥16px（触屏上）。** 小于这个数，iOS 会把整页放大，而且**没有任何办法缩回去**——之后这个页面就一直是放大且能横向拖动的状态。所以这条写在 `theme.css` 里，用 `@media (pointer: coarse)` 加 `!important` 一次管住所有 `input / select / textarea`：能被某个组件漏掉一个 class 就破功的规矩，不算规矩。
3. **键盘遮住的部分要让出来。** body 固定之后，键盘是盖上来而不是把页面顶上去的，Composer 会被压在键盘底下。Chrome 认 `interactive-widget=resizes-content`，Safari 不认，所以 `shell/viewport.ts` 监听 `visualViewport` 把「被盖住多少」写成 CSS 变量 `--keyboard`，Composer 拿它当 padding。写成 CSS 变量而不是 React state：这个值在键盘动画的每一帧都在变，让时间线跟着重绘是看得见的。
4. **`touch-action` 只在 `body` 上写 `manipulation`。** 曾经写的是 `pan-y`，本意是禁掉页面横拖，实际后果是——`touch-action` 是**沿祖先链取交集**的——里面那些自己声明了 `overflow-x: auto` 的面板（宽表格、长命令行）在触屏上也横拖不动了。禁横拖靠的是 `#root` 的 `overflow: hidden`，不是这个属性；`manipulation` 只去掉双击缩放（手机上几乎总是误触，而且同样很难缩回去）。

移动端走 Tauri Mobile（M2），加载的是同一份产物。这决定了两条现在就要遵守的纪律：

1. **触摸优先**：可点区域不小于 44px，不依赖 hover 才能发现的功能。窄屏上要靠 `min-h-11` 撑起来，然后用 `md:` 把桌面端改回紧凑值——反过来写（桌面尺寸打底、窄屏加大）会漏，因为漏掉的那个在宽屏上看着是对的。
2. **不假设有键盘**：任何快捷键都必须有可点的等价入口。

### 2.10 日志

**每一处报错旁边都有一个「查看日志」。** 顶栏的错误条、失败的这一轮对话，点进去开一个「日志」标签页。

标签页里读的是 daemon 的日志文件的**末尾**（`log.tail`，默认 64KB）：这些文件会长到几 MB，而有用的部分永远是刚刚发生的那一段。可以在目录里的几个文件之间切换、刷新、整段复制。

**内容走连接，不给路径。** 一条失败消息能说的只有一句话，剩下的经过在文件里；而看错误的人可能正拿着手机——那台机器上的路径对他没有任何意义。桌面端多一个「打开日志目录」按钮（浏览器里不显示：那个按钮在浏览器里什么都做不了，一个点了没反应的按钮比没有按钮更糟）。

## 5. 技术选型

| 层 | 选择 | 理由 |
|----|------|------|
| 框架 | React + TypeScript + Vite | 生态与招人面最宽；Windows/macOS Tauri 壳与移动浏览器复用同一套工作台代码和静态产物 |
| 样式 | Tailwind + CSS 变量主题 | 主题切换靠变量，不靠重新编译 |
| 服务端状态 | TanStack Query | 文件树、git、catalog 这类请求-缓存场景 |
| 客户端状态 | Zustand | 面板布局、草稿、会话时间线 |
| 终端 | xterm.js | 事实标准 |
| 编辑器 | CodeMirror 6 | 比 Monaco 轻很多，够用 |
| 高亮 | Shiki（预编译主题） | 与编辑器主题一致 |
| 图标 | Lucide | |

**不选 React Native / Expo**：跨平台价值主要在原生 App，而我们的桌面和手机都是 Tauri WebView，两者都吃 Web 产物；引 RN 只会平白多一层抽象和构建复杂度。

## 6. 状态与数据流

```
WebSocket（自有会话协议）
    │
    ├─ SessionEvent ──► timeline store（Zustand）──► 会话视图
    ├─ 推送快照     ──► TanStack Query 缓存失效  ──► 文件树 / git / 机器列表
    └─ PTY 输出     ──► 直接喂给 xterm，不进 store
```

三条规则：

1. **时间线不进 Query**：它是流，不是可缓存的请求结果。
2. **PTY 输出不进 store**：高频二进制流进状态管理只会拖垮渲染。
3. **每台机器一个连接与一份 store**，切换机器不互相污染。

## 7. 与桌面 / 手机壳的关系

同一份构建产物四处复用：浏览器直出、Tauri 桌面包、Tauri 移动包、自建部署的静态托管。

这一点值得说明白，因为它常被误解：**PC 端"不依赖 Node"并不意味着 PC 端不能用 H5**。Tauri 的窗口内容就是本项目这套前端，只是渲染它的是系统 WebView 而非 Chromium，驱动它的是 Rust 而非 Node。被排除的是 Node 运行时进程，技术栈本身没有任何降级（见 [desktop-client.md](./desktop-client.md) §4.1）。

宿主差异收敛在 `src/host/` 一个模块里，对外暴露统一接口：

```ts
interface Host {
  readonly kind: "browser" | "desktop";
  endpoint(): Promise<Endpoint | null>;      // 桌面问壳要本机端口，浏览器读 URL 片段
                                             // 会被再问一次：重连时地址可能已经变了，
                                             // 一次性的转发票据更是必须重新要一张
  notify(n: Notification): void;
  openExternal(url: string): void;           // 文档、发布页这类"外面的世界"
  openWindow?(url: string): void;            // 登录这类"还在本应用里"；缺失时退回上一行
  pickDirectory?(): Promise<string | null>;  // 可选能力，缺失即不渲染入口
}
```

**业务组件不允许出现 `if (isTauri)`。** 需要区分宿主时，要么走上面的接口，要么把该能力声明为可选并在缺失时隐藏入口——和处理 agent `Capabilities` 的做法一致（§2.2）。否则宿主分支会长满全项目，最后变成事实上的两套前端。

壳自身只提供四件事：**本机端点、深链、通知、目录选择**。任何"只有桌面能用"的功能都要先问一句能不能用 Web 能力实现。
