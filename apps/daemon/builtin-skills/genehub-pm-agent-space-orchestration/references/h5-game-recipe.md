# H5 项目拆分参考

这是起点，不是固定队形。按文件所有权、接口与可独立验收结果拆包，例如：

- 规则/模拟内核；
- H5 shell、输入与渲染适配；
- 内容/关卡注册表；
- 持久化或迁移 seam；
- 独立 Reviewer。

避免把 engine、UI、build、persistence 全塞进一个包，也不要拆成单文件 checkpoint。共享接口先冻结；兄弟包使用 fixture 验证各自边界，完整组合门禁在 accepted slices 合流后运行。

需要规模化内容时优先采用确定性生成器、统一模块接口和数据驱动差异；生成源码必须可达、可编译、被生产注册表遍历，并纳入测试和评审。排除依赖、vendor、构建输出、死代码和为了凑行数的重复。

交付必须有可直接体验的入口、确定性 smoke、生产 build 和清晰限制。Reviewer 关注用户行为、边界与集成 seam，不逐文件通读同构生成模块。
