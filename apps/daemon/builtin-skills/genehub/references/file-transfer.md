# 跨机文件传输

用于用户明确要求在 GeneHub 已授权机器之间上传、下载或续传文件。先记录源机器、源工作区和路径，
以及目标机器、目标工作区和路径；本机路径与远端路径分别按所属机器解析。

## 方向与范围

机器之间相互传文件可以统一为一种“源机器向目标机器发送”的能力，无需另做拉取机制：

- A 的文件给 B：在 A 发起发送，B 接收。
- B 的文件给 A：由 remote shell 在 B 触发同一种发送能力，A 接收。

这是专用传输能力的设计模型，不是已经可执行的命令。上传、下载只是相对当前操作者的称呼；每个
文件任务明确源与目标，不把“只实现一种发送能力”理解成只能固定 A→B。用户只要求传一个方向时，
完成该任务即可；要求顺序传输时，不主动扩大成双向并发、目录同步或整个工作区迁移。

remote shell 只负责启动和查询源机器上的传输任务，文件内容应走专用二进制传输流。在远端发起前，
核对源机器上的实际传输能力、命令绑定和隔离范围，以及到目标机器的可达性与写入权限。A 能执行 B
的 shell 不代表 B 已获得写入 A 的授权；不把 A 的 CLI 路径或会话凭据直接复制到 B 使用。缺少条件时
报告具体缺口，不因传文件自动扩大授权。

单向指文件内容方向，接收端仍需返回进度、校验结果、完成回执和错误。简化方向不降低用户提出的
文件大小、完整性或续传要求。

## 先发现实际能力

使用会话绑定的 `GENEHUB_CLI`，先读 `capabilities`；实际列出文件传输命令后，再读对应 `schema`。
用 `context` 和 `machine list --reachable` 核对源、目标身份与可达性。命令缺失时报告版本能力缺口，
不要把提议中的发送入口当成已经可执行的命令，也不要借传文件扩大配对或工作区权限。

当前 CLI 尚未提供专用跨机文件传输入口。现有路径的限制是：

- `shell` 一次输入最多 1 MiB。输入可以携带小脚本或小文件，但不是 GB 文件流式上传接口。
- `shell` 输出按文本处理，非 UTF-8 字节可能改变；默认 1 MiB 输出预算还会丢弃超出的中间部分。
  `--max-output 0` 只取消输出预算，不能恢复已经改变的二进制字节。Base64 也会增加体积和上下文消耗。
- 工作区 `file.write` 接受文本，`file.copy` / `file.move` 在同一工作区内操作。
  Asset Preview 的单文件上限为 64 MiB，不能作为几 GB 文件的传输方案。

用户要求 GB 文件时，当前应说明专用能力尚缺；不要通过打印文件或整份 Base64 到工具输出、聊天、
任务记录来模拟传输。上传反馈或会话附件的专用接口也不等于任意工作区文件传输。

## 执行与完成证据

当安装版本提供专用传输能力时，按其 schema 和实际限制执行。保留命令提供的传输标识、目标路径、
已确认进度与状态；进度描述只写摘要，不携带文件内容或凭据。覆盖已有目标按用户指定的冲突处理执行。

无论由哪台机器发起，完成均以目标机器接收端的最终落盘结果为准。核对声明长度与实际大小，
以及命令提供的 SHA-256 或其他完整性校验。只有开始回执、100% 已发送、进程退出 0 或临时文件存在，
都不足以声称文件已经完整交付。缺少最终结果时明确标为待核验。

连接中断后先查原传输状态和最终目标，再决定续传或重试；续传应绑定原源文件身份、目标和已确认偏移。
源文件已改变或结果未知时，不盲目重跑、覆盖目标或把部分文件当成功。取消、磁盘不足、权限拒绝与
校验失败按实际错误报告，保留仍可恢复的进度。

现有逻辑连接只在进程内保留短时恢复状态，默认恢复期限为 60 秒；这不证明文件能在长时间断网、
daemon 重启或客户端退出后续传。当前 remote CLI 使用 Relay/Fabric，不能把浏览器的 RTC 直连状态
当成该 CLI 任务的传输路径。报告网络实测时注明文件大小、方向、实际通道与环境；小文件用例通过
不等于几 GB 文件或持续传输已经验收。
