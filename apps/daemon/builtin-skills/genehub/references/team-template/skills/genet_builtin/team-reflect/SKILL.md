# 团队反思

先提升用户满意度，再改团队工作质量，同时防止反思空转。读本轮≤5000字符简报，沿卡、留言或 ghref 取相关事实，不扫全队历史。背景按需见 references/rationale.md。

1. 先核用户不满、纠偏、真实拒收，再红线/警告与失分，检查重复唤醒。沿原 ref 与原生状态区分事实；明确或来源未知的暂停不自动解除，用户未答不是客观阻塞。
2. 业务交还 Owner。目标未达、总授权和预算有效却无可执行工作时，沿原需求把具体差距交长期目标 Owner 自主续轮，不要求前台再派目标；阶段结算、无新消息或 activeGoalMs=0 不证明需求消失。
3. 本队规则沿公开扩展合同改，不复制调度器或加处置账本。归因不明由任务 Owner 先核查，缺证据再留平台归因，绕行并继续其它工作，不等外部接手。
4. 同一事实只处理一次；事实/严重度实质变化再处理。自己的报告、记忆、提交不构成新信号；无新信号就结束，不按整点或回合数巡查。
5. 有改动写清原信号、预期变化、下一次同类交付或自然卡的验收，无效撤回或换方案。只在唯一定义源维护、构建完整包，执行制品验证实际采用，不改生成物；只提交本轮验证过的改动，保留他人成果。字数上限见 team-core，编译指令≤32KiB。
6. 同一教训有两次独立 ghref 才沉淀岗位 index.md；跨角色高频经验再进根 memory.md（≤30行），不重复现有规则。无动作只结束原信号，不写报告、不提交快照、不更新记忆或发“已巡查”。

升级由本队自行审查、合并冲突、构建和验证，不等预合并；沿原维护项与已完成回执继续。按需读 references/upgrade.md 与平台反馈参考，质量口径见 team-core references/quality.md。已采用/等待不唤醒，不把维护核销给下一次反思。

采用后组织前台显式交接；本轮结果读入后按原合同交接同执行机新 Owner，先读 goal.md，旧 Owner 不派新单并收尾。业务文件只读，不搬旧材料、不发明转换命令。累计、副作用、暂停保留。普通维护不挂起等用户，不扩大权限或总预算。
