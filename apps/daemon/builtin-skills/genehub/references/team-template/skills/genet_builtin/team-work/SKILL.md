# 团队任务执行

开工核对原需求、taskId、当前职责、完成条件与授权边界。命令以 `"$GENEHUB_PYTHON" <团队根>/tools/run.py` 开头；唯一工作合同见 team-core `references/task-owner.md`。

- 一般任务做完一次交付并回原请求方；发现需要换方案多轮逼近目标时，沿原 Task 升级为长期目标并承接 Owner，同步前台一次后继续，不等回复、不重置预算或累计投入。
- 长期目标 Owner 对总体达成负责。读验收、上轮差距、延续任务、新意图、告警与预算，按 task-owner 合同在 `datas/goals/<目标编号>/` 写 `goal.md`/`index.md`；本轮 `iterations/<轮次>/plan.md` 与派单同回合写入，引用上轮总结。
- 一次派出全部可开工项后结束本轮；支持结果回精确请求方。阶段结束记录产物、已完成/延续/阻塞任务和剩余差距；总目标未达且授权仍有效，就自行规划下一轮，不把决定交回前台。
- 未满足原完成条件的任务跨迭代、换 SID、换 Owner 或返工仍沿原编号；成功交候选不代表目标通过，不能先结算再换号补完。连续多轮无进展就调整方案或验证方法。
- 超过半小时的任务组织实质并行，门槛和累计范围见同一合同；任何资源都按可同时使用规划，不以设备数量排队。只分开已证实的冲突，同一写目录用独立工位或副本；短任务直接完成，不制造空转凑人。
- Owner 按本轮子任务数安排：≥3 项至少一半时间用于管理，≥5 项只集成不实施，≥8 项配专业集成岗位，≥10 项可扩展子模块 Owner；不新增红线。目标预算的期限、会话总数、已用/剩余先手记 `goal.md`/`index.md`，未知不补零。
- 需要支持用 `task support <taskId> --space <岗位> --desc "<独立结果>" --request-id <稳定编号> "<输入、边界、产物与验收>"`；可同时派多项，然后结束本轮，不 sleep、不轮询、不用常驻 Agent 等待。
- Space 是身份和能力，会话承担工作。使用原派单的机器、分支和基线；独立目标可同 Space 并发，但写目录不重叠。需要修改前先认领独立工位并 `task bind-directory <taskId> --directory <绝对目录>`，不改公共配置给在途任务换项目。
- 收到结果核对实际提交、产物与验证，再整合自己的工位；共享集成/发布资源只在实际操作时串行。后台构建、测试或安装可按质量合同登记有界原生作业，同会话多个进程不算多人。
- 告警到达时处理具体实例，不固定每回合读全队告警。红线立即优先纠正；归因不明先由任务 Owner 核查，仍缺平台证据才留平台归因与原反馈。其它工作继续，尽量绕行，不等待回应、不找用户逐项批准。
- 已证实的局部冲突不冻结其它工作；重大风险附当前方案合并同步，Owner 在原授权内继续取舍。用户未答不是客观阻塞或停表理由。
- 收尾写本轮 `summary.md` 并更新 `index.md`，任务与 QA 证据入 `evidence/`，QA 原结论保留、纠正另追加。产物、验证及传输就绪后再 `task finish <taskId> --outcome success|failed|blocked "<结论与证据>"`，不得引用 `temp/`；成功须必需支持结算且已读入，中间回复不代表整体验收通过。
- QA 针对固定提交/制品实际操作，交付独立证据；不能凭源码或实施者自报判通过。持久数据从原交付入口验证升级保留；预览遵守 genehub-preview。
- 临时材料用 `temp new <slug> --task-id <taskId> --purpose "<用途>"`，正式产物和恢复来源不放可清理目录；未知回执不重派，旧工位不碰新租约。
- 整体达成、总期限/预算到达、明确暂停或取消时停止安排下一轮，保留原输入、锁和结论；不隐式恢复暂停、不重跑已完成副作用，不用换号或高成本模型绕过原授权。
- 新 Skill 只在新会话生效。升级后由团队按原控制合同交接给同执行机的新长期目标 Owner，先读 `goal.md`；旧根任务只作文件引用，旧 Owner/前台沿原任务收尾。累计、结论和暂停保留，旧 R6 边界未知，不批量迁移旧材料。
