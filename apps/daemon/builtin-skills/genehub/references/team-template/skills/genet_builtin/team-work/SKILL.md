# 团队任务执行

开工核原需求、taskId、职责、完成条件及授权；合同见 team-core references/task-owner.md，命令参数按需读 references/task-options.md。

- 一般任务完成一次交付回原请求方；需换方案多轮逼近目标时沿原 Task 承接长期目标，同步一次后继续，不等回复、不重置投入或预算。
- 长期目标 Owner 读验收、上轮差距、延续任务、新意图、告警、预算。在 datas/goals/<目标编号>/ 写 goal.md/index.md；本轮 iterations/<轮次>/plan.md 与派单同回合，引用上轮 summary.md。
- 用 `task support` 一次派出全部可开工项后结束本轮，不 sleep、不轮询。结果回精确请求方，核实际提交、固定制品与独立 QA 证据后整合；候选成功不等于目标通过。
- 阶段收尾写 summary.md，列交付、验证、延续/阻塞、差距与下一轮，更新 index.md。总目标未达且授权/预算有效就自行续轮，不等前台或用户。连续无进展则换方案或验证方法。
- 原完成条件未达时，返工、换 SID/Owner、跨迭代都沿原编号；不先结算再换号。超过半小时组织实质并行，任何资源按可并用规划，只分开实际冲突。同一写目录用独立工位/副本，原机器、分支和租约不乱换。
- 本轮子任务≥3项至少半时管理；≥5项只集成不实施；≥8项配集成岗位；≥10项可扩展子模块 Owner。目标总预算及已用/剩余手记 goal.md/index.md，未知不补零；调度额度不冒称自动总账。
- 红线立即优先纠正；归因不明由任务 Owner 先核原生事实，仍缺平台证据才留归因。局部冲突不冻结其它工作；重大风险附方案同步，日常取舍继续，不因用户未答停表。
- 产物、验证与传输就绪，持久 evidence/ 留任务和 QA 原结论（纠正追加），再 `task finish`。必需支持结算、已投递结果读入才可成功；不引用 temp/，不凭源码或实施者自报判 QA；持久数据从原交付入口验证升级保留。
- `task status` 沿原编号核未知；不重派已完成副作用。正式产物与恢复来源不放临时区，后台工作和资源按需登记，旧工位不碰新租约。
- 总体达成、总期限/预算到达、明确暂停/取消时停止新轮，保留输入、锁和结论；不隐式恢复，不换号或高成本模型绕过。
- 新身份须新会话；反思在本轮结果读入后按原控制合同交接同机新 Owner，先读 goal.md。旧 Owner 停止新派单并收尾；旧根任务仅引用，累计、结论、暂停保留，旧 R6 边界未知，不搬旧材料。
