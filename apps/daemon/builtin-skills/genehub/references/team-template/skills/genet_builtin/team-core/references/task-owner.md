# 任务、长期目标 Owner 与异步接力

团队工具复用原生会话、稳定派单、控制回执与单写者，不是另一套内核调度器。原生执行状态与协作等待分开；timer 从真实派单、输入与资源生成摘要，缺证据显示待核对，不按空闲处理。

## 从完成方式选择路径

- 答复本身就是结果、不需业务工位或独立验证：前台直接完成，不建 Task、不增加任务样本。
- 一次明确交付：前台选一个合适 Owner，任务完成后向前台交结论；互不依赖的交付可由不同 Owner 并行，不建迭代记录。
- 持续质量线、多轮打磨：前台开局交给一个有整合能力的长期目标 Owner。Owner 对总体达成负责，自行规划、执行、核查和续轮，前台只传人的新意图、按需查进展及合并重大风险。

分不清先按小的开始，触发即升级、只升不降。前台要写业务目录、构建/测试/真机或请岗位支持时转交 Owner。一次交付不足、需换方案逼近质量线时，原 Owner 沿原 Task 承接长期目标，同步一次后继续，不换 Task/SID、不重置创建时间、投入或总预算。不要向用户说内部类别或请用户分类。

## 长期目标的迭代

长期目标约束结果、范围、验收、总预算与期限；迭代是 Owner 达成目标的过程；任务有稳定编号、约定结果和完成条件。支持、后台作业与 QA 证据是任务的执行记录，不另加业务层级。

每轮在同一回合完成规划并派出全部可开工项：

1. 读原验收、上一轮产物与差距、延续任务、新意图、告警、剩余预算及资源。
2. 写阶段目标、可检查产物与验收方法，定“阶段结果达成或检查点到达，先到者为准”。
3. 列原任务引用、完成条件、依赖、可同时推进的工作和唯一设备安排；支持说明独立输入、边界、产物与验收。
4. 写风险与替代方案；连续多轮无进展时调整方案或验证方法，不原样再派一次修复。
5. 在已有任务描述和结果中保留上述规划及阶段总结，立即派出可开工项后结束本轮。当前没有独立迭代 CLI，不发明命令或另建调度账本。

结果到达由精确原请求方核对、整合和推进依赖任务。阶段收尾写制品、验证、已完成/延续/阻塞任务、剩余差距和下一轮计划。目标未达、总授权与预算仍有效就自行续轮，不等用户新消息、不交前台审批、不逐轮推送前台。

未达到原完成条件的任务跨迭代、换人、换 SID 或返工仍沿原任务累计；不以 success 标签或二十分钟支持把它变成多份短任务。原条件已达，后面新增独立要求，才是新任务。局部资源等待保留，其他可做工作继续；没有新事件才等待，不轮询或写巡查报告。

日常取舍由 Owner 在原授权内决定，重大风险带事实、影响和当前处理方案合并同步一次后继续；用户未答不是停表依据。整体达成、总预算/期限到达、明确暂停或取消时停止安排新轮。权限不足和真实外部依赖如实保留，不能借自主推进扩大范围或越过明确控制。

## 原任务命令与回执

- `task start --space ROLE --desc TEXT --request-id ID [--directory ABS] [--machine MACHINE] [--tier T|--model MODEL] GOAL`：前台建立任务与 Owner。重试读取同一编号原结果，不同内容拒绝；创建未知不换号重派。
- `task support TASK --space ROLE --desc TEXT --request-id ID ... GOAL`：Owner/子负责人请求支持，结果回精确请求会话，不自动改投前台。可同时派多项，派出后结束本轮。
- `task status TASK --summary`：先读有界收尾摘要。`ownWork` 只指本会话；Owner 的 `taskConclusion`、全任务的 `supports` 不能代替自己的收尾。跨机响应截断时保持未知，完整历史按需不带 `--summary` 查。
- `task send TASK --request-id ID TEXT`：追加原意图给精确 Owner。accepted 仅表示受理，不等于恢复、读入或完成；已结论任务另核原控制回执与 `recordedOutcome`、`capacityBudgetView`。
- `task bind-directory TASK --directory ABS`：本会话认领独立写工位。原生 cwd 可能是岗位 Space，实际操作明确业务路径；远端认领在原执行端完成，源端不创建同名目录。
- `task finish TASK --outcome success|failed|blocked EVIDENCE`：提交本会话真实结论。产物、验证和必要传输先就绪，不能先记结论再做十多分钟验证或拷贝。普通中间回复、支持成功和阶段结算不代表长期目标达成或 QA 通过。
- 整合结论可重复用 `--uses <子派单operationId>` 引用自己请求、已结论且实际读入的同任务产物；中途整合可在原生已完成回复单独写 `采用：ghref:item:...` 的精确结果引用。引用可省略，不另做逐项审批；只是有界整合声明，不冒称 Git 合入或真实用户验收。
- `task pause|resume|cancel TASK --request-id ID --expected-revision N [原话]`：按真实用户要求控制原任务树，原输入、暂停来源、支持与资源回执保留。发送成功不等于已停，查实际回执；普通通知不解除暂停。
- `task handover TASK --session SID --request-id ID --expected-revision N`：旧执行停止、资源核对后沿原任务交接，不重跑副作用。本版仅同机独立会话；跨机请求先拒绝，迁移须先交接真实产物和执行资源。

旧 failed/blocked 是真实阶段结论，持续授权未撤回不意味着原目标完成；但普通 send 不解除收尾门槛。用户明确继续时按实际控制归属用原 Task 显式 resume，完整旧结论保留 `conclusionHistory`，独立暂停的支持和失败输入不自动重试。来源未知的暂停不擅自恢复；新意图、阶段结论和 Human 控制分别保留。

## 并行、投入与调度配额

超过半小时的任务组织真实协作，不设“适不适合并行”的豁免。支持、整合、验证与同范围返工沿原任务；短任务直接完成，不拆碎、不启动无关 Agent 凑数。共享集成或发布资源只在实际操作时串行，其他工作继续。

R6 的档位与正式均值使用同一完整累计范围，小时至少十五分钟仅决定该卡是否考核：不足半小时不考核；半小时至不足一小时要求 0.75；一小时至不足两小时要求 1.5；两小时及以上要求 2。原生同会话执行和登记后台取并集，纯预览不算工作，读不到的贡献保留上下界，详见 quality.md。瞬时账本 `parallelism` 不是这个累计判据，决策以卡的 `required` 和正式上下界为准。

共享调度上限默认团队64活动会话、单任务累计32会话、任务年龄7200秒，对应 `TEAM_MAX_ACTIVE_SESSIONS`、`TEAM_TASK_MAX_SESSIONS`、`TEAM_TASK_MAX_AGE_SECONDS`。它们限制新派单，不是用户总期限，也不是任务必须到点结算；完成的支持不退还累计用量，不换号绕过。

长期目标 Owner 在原整体授权内核定调度额度，先读 `task budget TASK` 的实际上限、用量、budget revision 和阻塞原因。兼容入口为 `task budget TASK --max-sessions N --expires-at-ms MS --request-id ID --expected-budget-revision REV --reason TEXT`；调度 revision 与任务控制 revision 分开，重试复用原编号与参数。

当前旧账本可能仍把该命令绑定原前台：遵守真实返回的归属与回执，保留 Owner 的决定、记录平台不兼容并继续其它已授权工作，不绕过调用校验、不频繁叫醒前台代批。这不改变用户范围、总预算或总截止，不抹去累计用量、支持、暂停和租约，也不把 Agent 的调度决定写成 Human 新批准。

## 就绪结果、读入与资源

子结果就绪即独立排入精确请求方输入队列，不等父回合结束或同批其他子项。资源归还和结果入队分别对账，原用户暂停保留；排队不等于 Agent 读入，已登记后台仍未归还时保留原资源保护。

success 须必需支持全部结算并实际读入已投递的子结果与追加输入；失败结算不冒称通过。用原生 deliveredAtMs 核对交接，不凭 done 或锁已释放推读入。failed/blocked 仍须读入已投递项，但可以如实保留尚无结果的支持为 `finished.unresolvedWork`，不取消、恢复或释放它们的输入和写资源。

原生执行失败送达的是状态通知，不是业务结论或成功；之后恢复的真实成果单独计量。`task-settlement/2` 是原请求方的兼容状态提示，本地入队不等于送达/读入，不是新目标、续期、强制收尾或用户验收。修复者也不是结果接收方，成果仍回原 Owner。

## 跨机、部署与材料

唯一定义源和权威账本留在指定源机。岗位 `TEAM_MACHINE`、原接单机器/Space 与完整安装回执决定执行与回传，不按简称或目录猜目标；远端只装完整制品，不 clone 团队源或另起前台/timer。并发会话各用独立实际写目录，源端不代建远端路径。

现有 task-source 默认配置和原派单路由分开；改安装默认不改在途回传。旧端无协议时在创建前拒绝，沿原意图兼容升级后重试，不重建业务。协作摘要拒绝异源和旧版，新鲜度按接收本机时间，失效显示未知，不能替代原生执行或收尾。

模板发布不覆盖用户定制；在源端按正常升级合并、构建完整工具/岗位/身份制品，执行端 `verify --artifacts-only` 并回读实际采用。构建和安装不是业务或采用验收；旧记录和未决回执继续可读，冲突归原维护项处理。

临时材料用 `temp new NAME --task-id TASK` 放本会话独立目录，正式产物存 datas 或任务工位。任务、暂停、在途派单或未消费回执引用的材料不按 mtime 清理；适配器私有 state 不是业务临时区。执行未收尾不释放目录、端口或设备，旧工位不碰新租约。

## 旧记录兼容

旧 unitId、`--unit-of`、`--unit-stage` 和阶段推断只供既有记录兼容；新工作不要再维护一套评分业务单元，不用 new 或换 SID 拆开未完成条件。缺少可靠业务边界的旧长期容器显示未知，不能靠说明文字补造历史。

旧 `conclusionHistory` 的已结论等待以版本化 `concludedIntervals` 保留，不抹掉真实支持投入或资源义务；旧冻结事实按原版本解释。只有无 taskId 的老派单才沿旧 spawn/send 回执收尾，不另建任务重做。所有未知操作先核原编号，不凭最近活跃会话猜归属。
