# 团队工作质量

工作质量与项目成果分别验收，只有一个团队工作质量分。定时器做确定性采集和接力，不调用模型决定业务；Owner 推进目标，反思先提升用户满意度，再改工作质量并避免自身空转。

## 读卡与实际采用

`quality card`、`quality history`、`quality describe` 只读；`quality card --snapshot FILE` 可回放冻结事实。外部和诊断快照不能保存成官方采用卡；`quality facts` 只作即时诊断，不冒充到点自然卡。

卡的 `versions.teamTemplate.id` 来自实际工具、Skill 与入口内容；只有发布回执与这些内容一致才有 `releaseVersion`。缺回执、内容修改或采集中变化时保持未知。`versions.platformAtCapture` 单列各机安装版本，安装新内核不证明完整样板采用；完整源端、远端、身份与运行制品都核对，再看自然卡及实际行为。

当前发布口径仍为 tq/2 过渡模型，M1–M6 权重、锚点由 `quality describe` 列出；新的任务/迭代、M7/M8/R8 与校准模型尚不因本说明而生效。指标滚动24小时，红线取完整 UTC 整点小时；自然采集最近窗口的修订保留原卡，不覆盖历史。冻结事实重算字节一致，不同测量兼容键不拼连续达标。

正式分要求已知权重≥80%、该版本全部红线可判、窗口≥20闭环工作项；否则 score=null，暂定值、覆盖率与未知原因分别列出。没有工作负载不能出正式高分，拆支持不作为改善证据。项目通过、用户满意和工作分数不能互相代替。

## 当前红线与响应

R1：派单10分钟无回执；R2：非常驻成员空闲60分钟无结论；R3：结论10分钟未达、错投或重复；R4：未完成目标无因停摆15分钟；R5：结论后资源10分钟未归还；R6：完整累计任务范围的有效并行。每类触发该小时只扣一次50分，最低0；红线小时失格、连续数归零。

警告提前到负责方，在下个决策点组织调整；红线立即优先纠正，其它可做工作继续。同一实例事实不变不重复处理，实质变化再更新。归因不明先由任务 Owner 核查原派单、原生执行、结果与资源；仍缺证据或确认平台问题时，才留本队平台归因通道并尽量绕行。团队原因由任务负责人/Owner/反思处理；不假设产品里有另一个接手者、不等待回复、不逐条经前台转派。

兼容告警字段 `target=platform-development` 仅是平台归因标签，不是产品岗位或接手回执。错误归因才用 `quality triage <实例id> --attribution <来源> --evidence <依据>` 在原项补更正，旧备注与原证据保留；不增加登记时限、人工解除或重开窗口。

原生事实完整证明义务已消失时，timer 自动归档打开/关闭证据；还违约就下一小时继续判，缺事实就未知。历史未关闭实例不额外注入新卡。关闭红线不代表业务或用户目标验收通过。

## R6：完整范围累计，小时只作适用性和诊断

超过半小时的任务组织真实协作，不以“不适合并行”豁免，不派无关工作凑人。原完成条件未达时，修复、支持、整合、验证、换人和跨迭代都沿同一任务；长期目标年龄、支持份数或末尾整点切片不能重置或替代任务范围。

当前 `/4` 的过渡采集仍用稳定派单关联保留完整任务范围，内部 `unitId` 等兼容字段不要求 Agent 再维护第四种业务概念。缺可靠边界的旧开放目标保持未知，不按文件名、岗位或“第几轮”猜历史。

累计有效墙钟从完整范围起点至 min(结束,卡截止)，扣除该版本证实的控制排除区间；对应会话的原生回合与登记后台在相同区间取并集，再跨会话相加。一个会话多个进程仍只算一个人，前台不计，协调时间不能重复分给并发任务。归属不清保留上下界，不补零。

| 累计有效墙钟 | 门槛 |
| --- | --- |
| 不足0.5小时 | 不考核 |
| 0.5至不足1小时 | 0.75 |
| 1至不足2小时 | 1.5 |
| 2小时及以上 | 2 |

本小时有效墙钟至少15分钟才考核。`acceptance-unit-agent-hours/4` 用同一完整累计 Agent 工时/墙钟计算 low/high，档位范围与均值范围一致；low 达门槛通过，high 低于门槛触发，跨门槛未知。无适用任务为不适用，`required=null`；不能以新 SID、分单或重开阶段清时钟。

`taskParallelism` 每行带 taskId、兼容 unitId/operationIds、boundaryKnown、结束依据、实际 required、累计 totalEffectiveMs/totalAgentMs、正式 low/high。`aggregationScope=unit-to-card-end/1`；agentMs 和 hourLow/hourHigh 仍是小时投入与诊断，不混入累计裁决。在途瞬时 `parallelism` 也不是正式 R6。

累计高并行会平滑后段串行，正常收尾不因十六分钟片段重罚；小时下降可见，真实停滞仍由 R4 判断，不偷偷新增红线。整体授权/预算没有延长；用户明确暂停保留，团队自行“待用户决定”不是停止推进或洗掉历史违约的依据。

## 后台、派单与资源证据

有界构建、测试或安装用 `task job register TASK --job-id ID --pid PID --kind build|test|install|work --max-seconds N`，N为1至86400。PID 来自当前渠道原生 `genet process list`、属于本会话并排除预览服务，不用命名空间里的猜测 PID；登记不启动/终止进程。相同编号重试保留原登记，参数变化拒绝。

`task job status TASK --job-id ID` 读取实际状态；进程退出后 `task job finish TASK --job-id ID --exit-code N` 结算，仍运行时拒绝。只有原生身份与运行年龄可核且未超期限才延续工时；缺读数、进程消失或身份变化都不猜最后退出时间。退出码不是业务验收。

`registered-native-execution-union/2` 使证实的后台并入正式 R6，并从 R4 停滞区间扣除；回合与作业重叠不重复，暂停扣除，退出后不增长。`quality execution --snapshot FILE` 仍是独立诊断，不保存正式卡。

资源义务来自真实工位/写锁或远端租约，Agent 常驻进程本身不制造归还义务；有义务且原生进程仍在就仍占用，结论后超时继续判 R5。结果入队、读入、业务结论与资源归还分别核对，不因一项成功替代另一项。

## 采用、返工与时间成本

已读、读入十分钟的 inferred、有精确原生整合引用的 evidenced 分开。`task finish --uses OP` 只可引用本任务里本会话请求且已结论、已读入的支持；中途已完成原生回复可写 `采用：ghref:item:...` 精确引用结果。普通链接、引用例子、无时间或未完成回合不证明采用，不额外发登记消息。

M1 当前只计有界支持整合证据；Owner 根结论是目标边界，不是又一份支持。缺引用和真实返工关联仍进覆盖分母，不挑少数样本报100%；`--follows OP` 明示重做，正常 QA 或后续工作不自动返工。整体 failed/blocked 不抹掉有效整合引用；引用不等于真实项目验收或物理 Human 判定。

M4 按完整范围汇总 Owner、支持、整合和登记后台的会话区间并集，暂停扣除，同会话不重复；拆支持不增成本分母。未完工作单列累计，已完取滚动窗口结束样本；历史不全、共享归属不明只给下界和原因，不宣布更省。它是执行时间成本，不是实际金额。

可靠比较沿已有派单 `--parameters` 的 `qualityComparison`：schema=acceptance-comparison/1，有界 scope、正 size、固定 inputSha256/acceptanceSha256。只有相同声明、完整执行与整合证据的20个首样本才冻结本队可比时间基线；旧基线不借用，声明不证明 QA，通过不足就未知。

## 完整性、未知与归因

R7 用本机 `genet context` 的内核内嵌评分依赖摘要检查本地实际评分包，采集前后核对，不用团队可覆写基准；无关业务派单定制不在校验内。文件缺失、别名或不同使卡无效；读不到内核依据为未知。不能删检查或用旧健康缓存冒充当前证据。

原生执行失败状态通知保留输入、暂停及资源义务，不算成果首次送达或重复成果；真正业务 failed/blocked 仍是成果。真正重复、错投和未声明收件人继续判 R3。读取失败、采样缺口、无恢复样本和未知人工分类不补零。

失分按团队、模板、内核、厂商与待确认来源汇总，分组之和等于原账本，全部计入分数；责任来源不是已证实根因。日志负证据缺口不抹掉独立已读的原生回合、输入、派单与资源正证据。断言“无动作”须连续可覆盖观察，单次只读失败不是无工作。

## 冻结版本附录

- tq/1、task-agent-hours/1：沿各自旧事实解释；旧版小时在途门槛2不套新累计范围。
- task-agent-hours/2：根任务累计定档、旧小时比率；acceptance-unit-agent-hours/3：关联范围定档、旧小时比率。二者不改成 `/4` 解释。
- acceptance-unit-agent-hours/4：当前完整范围累计裁决；结论等待以 concludedIntervals 按版本保留，真实支持投入与资源义务不删除。
- dispatch-acceptance-unit/1、registered-native-execution-union/2：当前稳定关联与原生/后台并集；旧无 basis 的快照不解释新增字段。
- native-owner-use-reference/1、complete-acceptance-unit-time/1：当前整合引用与完整时间基线；不回填旧用户判定或成本。
- dispatch-resource-obligation/2、per-source-failure-domain/1：真实资源义务和逐源覆盖，旧事实保持原意。
- source-result-generation/2、native-minute-freshness/2：失败状态与成果分开、原生/分钟观察的新鲜度分开；旧快照不追补。
- native-embedded-team-scoring/1、native-hourly-facts/2：评分依赖完整性与小时原生违约，自动归档不重开24小时窗口。

各 basis 按卡上的 measurementVersion/streakCompatibilityKey 组合，不仅凭 tq/2 标签拼卡；影子回放与后补卡不代替首张自然正式卡。新任务/迭代及真实用户验收模型另经实现、回放校准、完整发布与采用生效，未实现的提案数值不是当前分数。
