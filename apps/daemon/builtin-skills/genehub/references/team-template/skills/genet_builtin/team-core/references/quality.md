# 团队工作质量

统一工作质量口径是 tq/2，独立于项目成果质量。默认样板定时采集，不调用模型、不改变派单；
反思简报带最新卡与失分账单，由团队自主决定改什么。不存在第二套核心分或项目分。

卡的 `versions.teamTemplate` 是本队实际运行样板版本的唯一采用依据：`id` 来自正在执行的内置工具、Skill 与入口文件内容；`releaseVersion` 只在升级回执与这些实际内容一致时显示。没有回执、内容后来修改或采集中发生变化时，发布版本保持未知，不能用平台安装版本或 platform 分支替代。`versions.platformAtCapture` 仍单列各机平台安装版本。版本元数据不改变指标、权重、口径或连续达标规则。

```
python3 tools/run.py quality card
python3 tools/run.py quality history
python3 tools/run.py quality describe
python3 tools/run.py quality card --snapshot <冻结事实文件>
```

`card`、`history`、`describe` 只读，不读取或清空业务收件箱。`card --save` 只允许重算并保存本队原生
采集目录中与内容哈希一致的快照；外部快照可离线分析，不能写成官方采用卡。

每张卡的红线窗口为完整 UTC 整点小时，只按该小时原生事实判定；指标始终取滚动24小时样本。
采集器轮流补算最近三个完整小时，迟到的真实结论产生新修订，保留原卡和事实，不清旧账或重置基线。
同一冻结事实重算字节一致。历史缺失、读取失败、旧内核无交接时间或观察不足均保持未知。

正式分需已知权重不少于80%、R1–R6全部可判、指标窗口至少20闭环工作项。否则 `score=null`，
暂定分和可能区间只用于定位差距；采集卡、构建成功或在线不等于达到质量目标。

R1 派单超过10分钟无回执；R2 非常驻成员空闲60分钟无结论；R3 结论10分钟后未达、错投或重复；
R4 未完成目标无因停摆15分钟；R5 结论后资源10分钟未归还；R6 按下文 tq/2 的累计有效时长分档判断。
旧 tq/1 快照的 R6 仍按有未完成目标期间实际开工且最终有结论的有效在途项小时均值低于2判断。
等用户和用户暂停期间排除，串行不豁免。
一次触发某类红线扣50分，最低0；没有负载不能凭空出正式高分。

旧 tq/1 的 R6 同时排除每个工作项自身的暂停、待用户时段。快照用原生执行区间与分钟观察保存活动下界和
排除区间；观察最多沿用125秒，真实执行优先于陈旧暂停采样。缺样时段仍在可能上界内，不当成工作
或零工作；只有已结论项的已知活动进入下界。上下界跨过2时保持未知。旧冻结快照保留原有重算语义，
新的真实观察只能产生新修订，不能覆盖旧卡。

`task support --follows <operationId>` 标出本队重做的原支持单；`--standing` 标记常驻支持，
不计 R2 或有限工作延迟。二者均可省略，不增加必填表单。已有请求重试保留原参数；新元数据不能
静默发给不支持的旧源端，先完成兼容更新。实际读入由原生 Agent 交接回执证明，排队不算开工或读入。
读入满十分钟仍只标 `inferred`；读入、推断与已有整合结论 `task finish --uses <operationId>` 的
有界引用分开。长目标中的中间整合，可在原回复单独一行写 `采用：ghref:item:...`（结果的精确原引用）；
采集器只记录完成原生回合中带时间的明确声明，并核对该产物已送达且已读入。仅放链接、引用例子、
尚未完成或无时间的回合均不能确认采用，不需要另发登记消息或等整个长目标结束。新 `adoptionBasis=native-owner-use-reference/1` 的 M1 只计支持结果，Owner 根结论是目标
边界，不是另一份支持产物。缺少引用或真实 `follows` 的闭环项仍进入证据覆盖分母，M1 保持未知，
不能挑少量有引用项显示100%。明确 `follows` 才证明重做；integration/verification 或同单元后续工作
不自动算返工。请求方整体目标为 `blocked` 或 `failed` 时，有效 `--uses` 仍保留；整体未通过不抹去已明确采用的支持产物。引用只证明请求方在原生结论中声明整合，不冒称实际 Git 合入或项目验收，也不改变原结论。

M1采用/返工、M2流转、M3人的占用、M4单位采用成本、M5空转、M6失败/恢复；权重与锚点由
`quality describe` 列出。每项列样本与未知原因。新 `costBasis=complete-acceptance-unit-time/1` 按完整验收单元的全阶段
Session 区间并集计算 Agent 时间，包括 Owner、支持和已登记后台，暂停扣除，同会话不重复。
拆成多份支持不能增加成本分母；未完单元单列累计投入，已完单元取滚动24小时内的结束样本。
卡列总量与缺失原因；共享 Owner 归属或原生历史不全时只是下界，不宣布更省。它是时间成本，不是金额。
可靠比较可沿既有派单 `--parameters` 提供 `qualityComparison` 对象：`schema=acceptance-comparison/1`、
有界 `scope`、正数 `size`、固定输入与验收契约的 `inputSha256`、`acceptanceSha256`（64位小写SHA256）。
只有这些声明全部一致的完整且有整合证据单元才能比较，声明本身不证明项目QA通过。
本队首20个可靠同范围单元冻结在 `baselines/complete-acceptance-unit-time-v1.json`；旧 `baseline.json`
不覆盖、不借用。缺少范围、原生执行证据或20样本时M4比较未知，先看总量。新采用和成本口径进入连续
计卡兼容键，不拼接旧口径，正式定级80%和20闭环门槛不降低，旧卡逐字保留。

`quality facts` 可即时采集当前诊断事实，写入诊断缓存，保持业务只读；它不是整点正式卡。外部快照和诊断事实的 `officialCapture=false`，不能作为团队采用验收证据。

## tq/2：长任务的R6（同口径连续计卡）

新采集卡明确标注model为tq/2。其余R1–R5、M1–M6及定级线不变；未标scoringModel的旧冻结事实仍按tq/1逐字重算，旧卡不覆盖，tq/1与tq/2默认不连续拼接。

R6按完整验收单元判断，包含同一产物的修复、集成与验证；用派单的稳定关联，参见 task-owner.md。
单元累计有效时长决定档位，不用其容器根目标的年龄。原任务和 SID 保留，重做、续接不重置单元。
缺失原生边界的旧开放目标保持未知，不把每份支持候选当作一个已完成迭代。
前台会话不计。同一会话的原生回合与已登记后台执行先取并集，再按会话求和；无需等待结论才计在途工时，
不把多个进程当多个 Agent。分母为单元有效墙钟，任务级暂停/等待用户控制区间扣除。
Owner 工时只分配给当时唯一可归属的单元；并发单元之间不能确定归属的部分进入未知上界，不重复计入下界。

本小时有效时长至少15分钟才考核，门槛按任务累计有效时长（扣除暂停、等待用户）分档：

| 累计有效时长 | 所需并行度 |
| --- | --- |
| 不足0.5小时 | 不考核 |
| 0.5小时至不足1小时 | 0.75 |
| 1小时至不足2小时 | 1.5 |
| 2小时及以上 | 2 |

Agent工时除本小时有效墙钟得到并行度。读不到的会话贡献0到1倍墙钟：下界达到本档门槛则通过，上界低于门槛则触发，其余未知。短任务不适用，不能为凑数拆碎或空转；无符合条件的任务为不适用。卡的 `taskParallelism` 列出每个任务的时长、工时、上下界、缺失会话、判定和实际 `required`；不足半小时的 `required=null`。R6 失分实例也带实际门槛。瞬时parallelism提示含协调等待，与这里累计原生工时不同。

新事实标注 `r6Basis=acceptance-unit-agent-hours/3`、`acceptanceUnitBasis=dispatch-acceptance-unit/1` 和
`executionBasis=registered-native-execution-union/2`，版本进入卡和连续达标兼容键。
`taskParallelism` 每行保留根 taskId，增加 unitId、operationIds、boundaryKnown、结束依据及实际 required。
旧 /2 仍用根任务分档，未标 r6Basis 的 /1 仍固定门槛 2；冻结重算和旧卡不改，不拼接不同版本的连续达标。
指标保持 24 小时滚动，原目标截止不重设。

## 失分归因

新采集的快照带 `team-quality-attribution-context/1`，每个红线实例和指标失分都有 attribution，卡与反思简报按团队、平台模板、内核、厂商及待确认来源汇总。自动派单确认、自动结果入队、自动资源归还由样板机制承担义务；归因中的 `operational-responsibility/1` 表示责任来源，不能直接当作根因已经证实。失败、唤醒原因和派单分段尚无足够事实时，明确保持待确认，不猜成团队或厂商问题。

平台、内核和厂商失分照常计入，分组总额等于原失分账本；每类红线仍只扣一次，不因实例数再次放大。没有测量值与有失分但原因待确认分别展示。此改动不改 tq/2 的分数或阈值，旧快照没有该元数据时保持原始逐字节结果；完整新模型和用户验收校准完成前，过渡卡不作为本期达标证据。
## 执行事实诊断（尚不改变 tq/2 算法）

`quality facts` 额外记录 `dispatchTiming`：平台准备/写锁等待使用源端 ACK 观测上界；会话开工等待使用执行端原生输入接受到首个 Round 的时间。两者分别带时钟与责任来源，不能直接相加，也不跨机器相减。ACK 上界不是精确排队时长。

需要让后台构建、测试、安装等有界作业进入执行证据时，任务内会话可用 `task job register <taskId> --job-id <稳定编号> --pid <PID> --kind build|test|install|work --max-seconds <1..86400>`。PID 取当前渠道 `genet process list` 的原生清单；隔离环境内的子进程 PID 可能属于不同 PID 命名空间，不能直接代入。登记只接受原生进程清单中属于当前会话的进程，排除预览服务；不启动或终止进程。相同编号重试保留原登记，参数变化拒绝。`task job status <taskId> --job-id <编号>` 回读并观测；进程退出后用 `task job finish <taskId> --job-id <编号> --exit-code <退出码>` 结算，进程仍在时拒绝结算。声明退出码不等于业务验收。

定时器仅延续有原生 PID/运行年龄证据且未超出登记期限的区间。读取失败、进程不再出现或身份变化都不延长工时，不猜测最后退出时间；未登记的预览服务器不会自动算作工作。`quality execution --snapshot <文件>` 仍是独立诊断投影，不保存正式卡。
新卡显式使用 registered-native-execution-union/2：已证实后台工作参与正式 R6，并从 R4 停滞区间扣除。
同会话回合和作业重叠只算一次，暂停扣除，退出后不增长；旧快照没有该版本时仍沿用原义。

## 资源义务测量修正

新采集事实标注 `resourceObligationBasis=dispatch-resource-obligation/2`，卡的
`measurementVersion` 与 `streakCompatibilityKey` 为 `tq/2+dispatch-resource-obligation/2`。
资源义务来自实际工位/写锁绑定或远端派单租约；没有租约的 Agent 常驻运行进程不产生归还义务。
存在真实义务时，原生进程仍在则仍算占用，结论后 10 分钟未归还仍触发 R5；释放保护不变。
旧事实缺少该标记时保留原始重算结果，不修改历史卡，不把新旧测量口径拼成连续达标。
此修正仍是过渡口径，完整目标口径完成前不能作为本阶段目标完成证据。

## 独立证据覆盖

新事实另标 `evidenceCoverageBasis=per-source-failure-domain/1`，与资源口径一起进入
`measurementVersion` / `streakCompatibilityKey`，不同版本不拼接。账本变动/巡检日志的单次写入失败，
只影响对应时间段的账本负证据；不能抹去已独立读取的原生回合、输入、派单和资源证据。
原生读取失败仍保持未知，未识别的旧事件失败仍保守影响生命周期覆盖。空转唤醒只有连续观测、
且该原生执行区间没有日志缺口时才能断言“无变动”；正向变动有真实事件即可确认。
缺少人工介入分类或恢复样本仍显示未知，不补零，不改历史卡。
# 红线的自动归档与连续计数

新采集采用 `native-hourly-facts/2`。违约仍在（如资源仍未归还、长任务本小时仍低并行）则自然再次触发；违约已消失，下一小时不再扣分。历史未关闭实例不会额外注入新卡，旧卡和冻结事实不改。读取不完整时保持未知，不以无数据当作解除。

定时器按完整原生观察自动关闭并归档原实例的归因、打开证据、关闭事实与时间，不需要人工命令。红线所在小时的卡失格，连续达标计数归零，这就是重新计时；指标仍滚动24小时，不因关闭启动新窗口或清除样本。新旧口径不拼接连续达标。关闭事件不等于项目成果或用户目标已验收。

红线按自动归因直接通知：团队问题通知 Owner 与反思，平台或待确认来源进入平台告警，不再自动生成平台反馈文件。没有归因登记时限、超时或连续两小时升级。判断有误时可用 `quality triage <实例id> --attribution <更正来源> --evidence <依据>` 补更正备注；可再次更正，旧备注与原自动归因仍自动存档。普通处理无需新命令，下一张卡按事实复核。
